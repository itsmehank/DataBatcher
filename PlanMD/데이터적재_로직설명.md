### bulk_update.py와 daily_update.py 실행 로직 상세 가이드

이 문서는 DataBatcher 프로젝트의 두 가지 핵심 데이터 수집 스크립트의 실행 로직을 단계별로 설명합니다.

---

## 1. bulk_update.py - 전체 종목 일괄 수집

### 목적
과거 데이터를 대량으로 수집하여 DB를 초기 구축하거나, 장기간의 히스토리 데이터를 한번에 채우는 작업입니다.

### 실행 흐름

#### STEP 1: 초기화 및 설정 로드
```python
# 1-1. 설정 파일 로드
config/settings.yaml 파일에서 DB 연결 정보, 지표 설정 등을 읽어옴

# 1-2. DB 엔진 생성
DBManager.get_engine()을 통해 MySQL 연결 풀 생성

# 1-3. 커맨드라인 인자 파싱
--start: 시작일 (예: 2024-01-01)
--end: 종료일 (예: 2024-12-31)
--market: KOSPI/KOSDAQ/KONEX/ALL
--top: 시가총액 상위 N개 (옵션)
--workers: 병렬 처리 워커 수 (기본값: 4)
```

#### STEP 2: 종목 목록 로드
```python
# 2-1. symbol_master 테이블에서 ACTIVE 종목 조회
SELECT symbol, name, market 
FROM symbol_master 
WHERE status = 'ACTIVE'
AND market = '{지정한 마켓}'  -- 옵션
ORDER BY symbol
LIMIT {top}  -- 옵션

# 2-2. 결과: [(symbol, name, market), ...] 리스트
예: [('005930', '삼성전자', 'KOSPI'), ('000660', 'SK하이닉스', 'KOSPI'), ...]
```

#### STEP 3: 병렬 처리 준비
```python
# 3-1. RateLimiter 초기화
초당 5회 API 호출 제한 (FDR API rate limit 준수)

# 3-2. 공통 컴포넌트 생성
- KRStockCollector: FDR API를 통한 가격 데이터 수집
- IndicatorPipeline: 지표 계산 (SMA, EMA 등)
- IndicatorSaver: DB 저장 담당

# 3-3. ThreadPoolExecutor 생성
워커 수만큼 스레드 풀 생성 (예: 4개)
```

#### STEP 4: 각 종목 병렬 수집 (`collect_single_symbol` 함수)

**4-1. Rate Limiting**
```python
rate_limiter.acquire()  # API 호출 전 대기 (초당 5회 제한)
```

**4-2. 가격 데이터 수집**
```python
df_price = collector.fetch(symbol, start=start_date, end=end_date)
# FDR API 호출 → Yahoo Finance에서 OHLCV 데이터 가져옴
# 반환: DataFrame with columns [date, open, high, low, close, volume]
```

**4-3. 데이터 검증**
```python
df_price = collector.validate(df_price)
# - 필수 컬럼 존재 확인 (open, high, low, close, volume)
# - 결측치 제거
# - 가격 음수 체크
```

**4-4. 가격 데이터 저장 (INSERT ONLY)**
```python
price_rows = collector.save(df_price, symbol, mode="insert_only")
# → stock_prices 테이블에 INSERT
# mode="insert_only": 이미 존재하는 (symbol, date)는 건너뜀 (기존 데이터 보존)
# 반환: 실제로 INSERT된 행 수
```

**4-5. 지표 계산**
```python
# DataFrame을 DatetimeIndex로 변환
dfp = df_price.copy()
dfp["date"] = pd.to_datetime(dfp["date"])
dfp.set_index("date", inplace=True)

# 파이프라인 실행
outputs = pipeline.run(dfp)
# config에 정의된 지표 계산:
# - sma_5_close: 5일 이동평균
# - sma_20_close: 20일 이동평균
# - ema_12_close: 12일 지수이동평균
# - ema_26_close: 26일 지수이동평균
# 반환: {indicator_name: pd.Series, ...}
```

**4-6. 지표 데이터 변환**
```python
df_long = pipeline.to_long_dataframe(
    symbol=symbol,
    market=market,
    source="FDR",
    outputs=outputs
)
# Wide format → Long format (EAV 패턴) 변환
# 결과 예시:
# | symbol | date       | indicator    | params_hash | value     | market | source |
# |--------|------------|--------------|-------------|-----------|--------|--------|
# | 005930 | 2024-01-02 | sma_5_close  | abc123...   | 10490.50  | KOSPI  | FDR    |
# | 005930 | 2024-01-02 | sma_20_close | def456...   | 10320.25  | KOSPI  | FDR    |
```

**4-7. 지표 데이터 저장 (INSERT ONLY)**
```python
indicator_rows = saver.save_long(df_long, mode="insert_only")
# → stock_indicators 테이블에 INSERT
# mode="insert_only": 기존 (symbol, date, indicator, params_hash) 건너뜀
# 반환: 실제로 INSERT된 행 수
```

#### STEP 5: 결과 집계 및 리포트
```python
# 5-1. 성공/실패 분류
success_results = [r for r in results if r["status"] == "success"]
failed_results = [r for r in results if r["status"] == "error"]

# 5-2. 실패 종목 로그 기록
logs/bulk_update_failed.log 파일에 실패 종목 정보 저장
형식: {symbol}\t{name}\t{market}\t{error_message}

# 5-3. 요약 출력

```

### 생성되는 데이터

#### stock_prices 테이블
```
각 종목 × 날짜별 가격 데이터
예: 100개 종목 × 252영업일 = 약 25,200행
```

#### stock_indicators 테이블
```
각 종목 × 날짜 × 지표 개수
예: 100개 종목 × 252영업일 × 4개 지표 = 약 100,800행
```

## 2. daily_update.py - 일일 증분 업데이트

### 목적
장 마감 후 최신 데이터를 수집하고, 이미 완료된 과거 데이터는 건드리지 않으면서 효율적으로 업데이트합니다.

### 실행 흐름

#### STEP 1: 초기화 및 검증
```python
# 1-1. 설정 로드
config/settings.yaml 에서 DB 정보, 타임존, 마켓 마감시간 등 로드

# 1-2. 커맨드라인 인자 파싱
--symbols: 특정 종목 리스트 (예: 005930 000660)
--all: symbol_master의 모든 ACTIVE 종목
--market: KOSPI/KOSDAQ/KONEX/ALL (--all과 함께 사용)
--top: 상위 N개 (--all과 함께 사용)
--force: 마감시간 체크 무시

# 1-3. 마켓 마감 체크 (--force 없을 때만)
현재 시간이 장 마감시간(16:00) + 안전버퍼(30분) 이후인지 확인
→ 아니면 "아직 실행 시간이 아닙니다" 메시지 출력 후 종료

# 1-4. 종료일 계산
기본값: 마지막 영업일 (get_last_business_day 함수 사용)
사용자 지정: --end YYYY-MM-DD
```

#### STEP 2: 종목 목록 결정
```python
if args.all:
    # symbol_master 테이블에서 조회
    SELECT symbol FROM symbol_master
    WHERE status = 'ACTIVE'
    AND market = '{지정한 마켓}'  -- 옵션
    LIMIT {top}  -- 옵션
else:
    # 커맨드라인에서 지정한 종목 사용
    symbols = args.symbols
```

#### STEP 3: 각 종목별 처리 (`process_symbol` 함수)

**3-1. 최근 30일 가격 수집 (INSERT ONLY)**
```python
start_30 = end_date - timedelta(days=30)

# FDR API 호출
df_new_price = collector.fetch(symbol, start=start_30, end=end_date)

# 검증
df_new_price = collector.validate(df_new_price)

# stock_prices 테이블에 INSERT ONLY
new_rows = collector.save(df_new_price, symbol, mode="insert_only")
# → 기존에 없는 날짜만 추가 (예: 오늘 날짜 1행)

출력: "005930: 가격 1건 신규 추가"
```

**3-2. DB에서 최근 250일 데이터 조회**
```python
start_250 = end_date - timedelta(days=250)

# stock_prices 테이블에서 조회
SELECT date, open, high, low, close, volume
FROM stock_prices
WHERE symbol = '005930'
AND date BETWEEN start_250 AND end_date
ORDER BY date

# 반환: DataFrame (약 180~200행, 영업일 기준)
```

**3-3. Warmup 데이터 포함하여 재조회**
```python
# 지표 계산에 필요한 warmup 기간 계산
warmup = pipeline.warmup_days()  
# 예: EMA 26일 → warmup = 26일

start_with_warmup = start_250 - timedelta(days=warmup)

# 확장된 기간으로 다시 조회
df_full = load_price_data(engine, symbol, start_with_warmup, end_date)
# → 약 200 + 26 = 226행
```

**3-4. 전체 구간에 대해 지표 계산**
```python
# DatetimeIndex 설정
dfp = df_full.copy()
dfp["date"] = pd.to_datetime(dfp["date"])
dfp.set_index("date", inplace=True)

# 파이프라인 실행
outputs = pipeline.run(dfp)
# → {sma_5_close: Series, sma_20_close: Series, ...}
# 각 Series는 warmup 이후 모든 날짜에 대한 계산값 포함
```

**3-5. 최신 날짜부터 역순 처리 (Smart Early Stop)**
```python
# 250일 구간의 날짜 목록 (최신 → 과거 순)
dates_desc = sorted(df_250["date"].unique(), reverse=True)
# 예: [2024-12-31, 2024-12-30, 2024-12-29, ...]

for target_date in dates_desc:
    # (a) 완료 체크: 해당 날짜의 모든 지표가 이미 DB에 있는지 확인
    if checker.is_complete(symbol, target_date):
        print(f"{symbol}: {target_date} 모든 지표 완료 → 중단")
        break  # ← 이미 완료된 날짜 만나면 즉시 중단 (효율성 핵심)
    
    # (b) 해당 날짜의 지표만 추출
    df_long_date = extract_indicators_for_date(
        symbol=symbol,
        target_date=target_date,
        outputs=outputs,
        pipeline=pipeline
    )
    # 결과 예시 (2024-12-31 하루치만):
    # | symbol | date       | indicator    | params_hash | value    |
    # |--------|------------|--------------|-------------|----------|
    # | 005930 | 2024-12-31 | sma_5_close  | abc123...   | 10500.00 |
    # | 005930 | 2024-12-31 | sma_20_close | def456...   | 10450.00 |
    # | 005930 | 2024-12-31 | ema_12_close | ghi789...   | 10520.00 |
    # | 005930 | 2024-12-31 | ema_26_close | jkl012...   | 10480.00 |
    
    # (c) UPSERT (덮어쓰기 허용)
    rows = saver.save_long(df_long_date, mode="upsert")
    # → stock_indicators 테이블에 UPSERT
    # mode="upsert": 존재하면 UPDATE, 없으면 INSERT
    # 이유: 최신 날짜는 당일 데이터가 수정될 수 있으므로
    
    total_upserted += rows
    processed_dates += 1

출력: "005930: 3개 날짜 처리, 지표 12건 업서트"
```

**3-6. IndicatorChecker의 완료 로직**
```python
# checker.is_complete(symbol, date) 내부 동작:

# 필요한 지표 목록 (config에서 정의)
required_indicators = ['sma_5_close', 'sma_20_close', 'ema_12_close', 'ema_26_close']

# DB에서 해당 날짜의 지표 개수 조회
SELECT COUNT(DISTINCT indicator)
FROM stock_indicators
WHERE symbol = '005930'
AND date = '2024-12-20'
AND indicator IN ('sma_5_close', 'sma_20_close', 'ema_12_close', 'ema_26_close')

# 개수가 4개(전체)면 완료
return count == 4
```

#### STEP 4: 결과 출력
```python
# 각 종목마다 출력 예시:
005930: 가격 1건 신규 추가
005930: 3개 날짜 처리, 지표 12건 업서트

000660: 가격 0건 신규 추가  ← 이미 최신 데이터 있음
000660: 2024-12-31 모든 지표 완료 → 중단  ← Early stop 발동
```

### 생성/업데이트되는 데이터

#### stock_prices 테이블
```
신규 추가: 각 종목 × (오늘 날짜만, 없을 경우)
예: 1,000개 종목 × 1행 = 약 1,000행 추가
```

#### stock_indicators 테이블
```
UPSERT: 각 종목 × (업데이트 필요한 날짜) × 4개 지표
예: 1,000개 종목 × 평균 3일 × 4개 지표 = 약 12,000행 업데이트
```

## 3. 두 스크립트의 차이점 요약

| 항목 | bulk_update.py | daily_update.py |
|------|----------------|-----------------|
| **목적** | 과거 데이터 대량 수집 | 최신 데이터 증분 업데이트 |
| **수집 기간** | 사용자 지정 (예: 5년) | 최근 30일 |
| **처리 범위** | 전체 기간 | 최근 250일 (warmup 포함) |
| **병렬 처리** | O (ThreadPoolExecutor) | X (순차 처리) |
| **Early Stop** | X | O (완료된 날짜 만나면 중단) |
| **저장 모드** | INSERT ONLY | 가격: INSERT ONLY<br>지표: UPSERT |
| **실행 시간** | 10~30분 (전체 종목) | 5~20분 (전체 종목) |
| **사용 시점** | 초기 DB 구축, 장기 보완 | 매일 장 마감 후 |
| **Rate Limit** | 초당 5회 (병렬) | 초당 5회 (순차) |

## 4. 데이터 흐름도

### bulk_update.py
```
1. symbol_master 테이블 조회
   ↓
2. FDR API → 가격 데이터 수집
   ↓
3. stock_prices 테이블 INSERT ONLY
   ↓
4. 메모리에서 지표 계산 (IndicatorPipeline)
   ↓
5. stock_indicators 테이블 INSERT ONLY
```

### daily_update.py
```
1. symbol_master 테이블 조회
   ↓
2. FDR API → 최근 30일 가격 수집
   ↓
3. stock_prices 테이블 INSERT ONLY
   ↓
4. stock_prices 테이블 → 최근 250일 조회
   ↓
5. 메모리에서 지표 계산 (warmup 포함)
   ↓
6. 최신 날짜부터 역순으로:
   - stock_indicators 조회 (완료 체크)
   - 완료되지 않은 날짜만 UPSERT
   - 완료된 날짜 만나면 중단 ← Early Stop
```

## 5. 핵심 최적화 전략

### INSERT ONLY 모드 (bulk_update.py, daily_update.py 가격 데이터)
- **목적**: 과거 데이터 보존, 중복 방지
- **장점**: 
  - 재실행 시 이미 있는 데이터 건너뜀 → 빠름
  - 데이터 무결성 유지 (기존 데이터 덮어쓰기 방지)

### UPSERT 모드 (daily_update.py 지표 데이터)
- **목적**: 최신 데이터 갱신 허용
- **사용 이유**: 당일 데이터는 수정 가능성 있음 (예: 수정주가 반영)

### Early Stop (daily_update.py)
- **목적**: 불필요한 DB 쓰기 방지
- **효과**: 
  - 첫 실행: 250일 전부 처리
  - 두 번째 실행: 최신 1일만 처리 후 중단
  - 실행 시간 95% 단축

### Warmup 기간 (daily_update.py)
- **목적**: 이동평균 계산 시 필요한 과거 데이터 확보
- **예시**: EMA 26일 계산 → 26일치 과거 데이터 필요
- **효과**: 계산 정확도 보장
