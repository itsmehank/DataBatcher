### (1) 설정 파일 로딩 순서 및 사용 시점

#### 설정 파일 로딩 메커니즘

`bulk_update.py`와 `daily_update.py` 모두 `core/config_loader.py`의 `load_settings()` 함수를 사용하여 설정을 로드합니다. 로딩 순서는 다음과 같습니다:

```python
# core/config_loader.py (23-48 라인)
def load_settings() -> Dict[str, Any]:
    """Load configuration with the following precedence:
    1) Environment variable DATABASE_URL (overrides database.url)
    2) config/settings.dev.yaml if exists and has include: settings.yaml
    3) config/settings.yaml (base)
    Returns a merged dictionary.
    """
```

#### 우선순위 (낮음 → 높음)

| 순서 | 파일/설정 | 역할 | 우선순위 |
|------|----------|------|---------|
| 1 | `config/settings.yaml` | **기본 설정** (템플릿) | 낮음 |
| 2 | `config/settings.dev.yaml` | **개발 환경 오버라이드** | 중간 |
| 3 | `DATABASE_URL` 환경변수 | **DB URL 오버라이드** | 높음 (최우선) |

#### 각 파일의 사용 시점

##### `config/settings.yaml`
- **역할**: 프로젝트 전체의 기본 설정 템플릿
- **사용 시점**: 항상 먼저 로드됨 (base configuration)
- **특징**:
  - 모든 설정 항목의 기본값 정의
  - 프로덕션/개발 환경 공통 설정
  - DB URL은 플레이스홀더 (`USER:PASS@HOST`)
- **예시 용도**:
  ```yaml
  # 프로덕션 서버 배포 시 이 파일만 수정
  database:
    url: mysql+pymysql://prod_user:prod_pass@prod_server:3306/market
  ```

##### `config/settings.dev.yaml`
- **역할**: 로컬 개발 환경 전용 설정 오버라이드
- **사용 시점**: 파일이 존재하면 `settings.yaml` 위에 덮어씌움
- **특징**:
  - 로컬 Docker MySQL 접속 정보 (실제 계정/비밀번호)
  - 개발 환경에 맞춘 파라미터 (워커 수, 배치 크기 감소)
  - Git에 커밋하지 않음 (`.gitignore`에 추가 권장)
- **예시 값**:
  ```yaml
  database:
    url: mysql+pymysql://<user>:<password>@127.0.0.1:3306/trade
    pool_size: 5  # 개발 환경이라 작게 설정
  runtime:
    thread_workers: 6  # 프로덕션보다 적게
  ```

##### `DATABASE_URL` 환경변수
- **역할**: DB 접속 정보의 최우선 오버라이드
- **사용 시점**: 환경변수가 설정되어 있으면 무조건 우선 적용
- **특징**:
  - 컨테이너/클라우드 배포 시 유용 (설정 파일 수정 불필요)
  - 민감 정보를 코드와 분리
- **예시**:
  ```bash
  # 환경변수 설정
  export DATABASE_URL="mysql+pymysql://user:pass@production-db:3306/market"
  
  # 스크립트 실행 시 자동으로 이 URL 사용
  python scripts/bulk_update.py --start 2024-01-01 --end 2024-12-31
  ```

#### 실제 병합 동작 예시

```yaml
# settings.yaml (base)
database:
  url: mysql+pymysql://USER:PASS@HOST:3306/market
  pool_size: 10
runtime:
  thread_workers: 8
  batch_size: 2000

# settings.dev.yaml (override)
database:
  url: mysql+pymysql://USER:PASS@127.0.0.1:3306/trade
  pool_size: 5
runtime:
  thread_workers: 6

# 최종 병합 결과 (settings.dev.yaml이 존재할 때)
database:
  url: mysql+pymysql://USER:PASS@127.0.0.1:3306/trade  # ← dev 우선
  pool_size: 5  # ← dev 우선
runtime:
  thread_workers: 6  # ← dev 우선
  batch_size: 2000  # ← base에서 상속 (dev에 없으므로)
```

#### 권장 사용 패턴

| 환경 | 사용 방법 | 파일 수정 |
|------|----------|----------|
| **로컬 개발** | `settings.dev.yaml` 생성/수정 | `settings.dev.yaml` |
| **프로덕션 서버** | `settings.yaml` 직접 수정 | `settings.yaml` |
| **Docker/K8s** | 환경변수 `DATABASE_URL` 사용 | 없음 (환경변수만) |
| **CI/CD 테스트** | 환경변수 사용 | 없음 |

## 1. database (데이터베이스 연결 설정)

### 개요
MySQL 데이터베이스 연결 및 커넥션 풀 관리 설정입니다.

### 설정값

#### `url` (필수)
- **타입**: `string`
- **설명**: SQLAlchemy 데이터베이스 URL
- **형식**: `mysql+pymysql://사용자:비밀번호@호스트:포트/데이터베이스?옵션`
- **기본값**: `mysql+pymysql://USER:PASS@HOST:3306/market?charset=utf8mb4`
- **예시**:
  ```yaml
  url: mysql+pymysql://YOUR_DB_USER:YOUR_DB_PASSWORD@127.0.0.1:3306/market?charset=utf8mb4
  ```
- **주의사항**:
  - `charset=utf8mb4` 필수 (한글 종목명 저장)
  - 프로덕션: 실제 계정 정보로 변경 필요
  - 개발: `settings.dev.yaml`에서 오버라이드 권장

#### `pool_size`
- **타입**: `integer`
- **설명**: 커넥션 풀의 기본 크기 (동시 유지 연결 수)
- **기본값**: `10`
- **권장값**:
  - 개발: `5`
  - 프로덕션: `10-20`
- **영향**: 많을수록 동시 처리 성능 향상, 메모리 사용 증가

#### `max_overflow`
- **타입**: `integer`
- **설명**: pool_size를 초과하여 생성 가능한 추가 연결 수
- **기본값**: `20`
- **의미**: 최대 동시 연결 = `pool_size + max_overflow`
- **예시**: `pool_size=10`, `max_overflow=20` → 최대 30개 연결

#### `pool_recycle`
- **타입**: `integer` (초)
- **설명**: 연결을 재활용하기 전 대기 시간 (MySQL 타임아웃 방지)
- **기본값**: `1800` (30분)
- **권장값**: MySQL `wait_timeout`보다 짧게 설정 (MySQL 기본값: 8시간)
- **이유**: 장시간 유휴 연결을 재생성하여 "MySQL server has gone away" 에러 방지

#### `pool_pre_ping`
- **타입**: `boolean`
- **설명**: 연결 사용 전 유효성 체크 여부
- **기본값**: `true`
- **효과**: 끊어진 연결 자동 감지 및 재연결
- **권장**: 항상 `true` (안정성 향상)

## 2. runtime (실행 시간 파라미터)

### 개요
스크립트 실행 시 동작 방식을 제어하는 런타임 설정입니다.

### 설정값

#### `timezone`
- **타입**: `string`
- **설명**: 시스템 타임존 (한국 시장 기준 시간 계산용)
- **기본값**: `Asia/Seoul`
- **사용처**: `core/date_utils.py`에서 영업일 판단, 장 마감 시간 체크
- **예시**:
  ```yaml
  timezone: Asia/Seoul  # 한국
  timezone: America/New_York  # 미국 동부
  ```

#### `thread_workers`
- **타입**: `integer`
- **설명**: `bulk_update.py`에서 사용하는 병렬 처리 워커 수
- **기본값**: `8`
- **권장값**:
  - 개발/테스트: `4-6`
  - 프로덕션: `8-16`
- **주의**: `rate_limit_per_sec`과 함께 고려 (너무 많으면 API 차단 위험)
- **영향**: 많을수록 수집 속도 빠름, CPU/네트워크 사용 증가

#### `batch_size`
- **타입**: `integer`
- **설명**: DB INSERT 시 한 번에 처리할 행 수
- **기본값**: `2000`
- **권장값**:
  - 개발: `1000`
  - 프로덕션: `2000-5000`
- **영향**: 클수록 DB 성능 향상, 메모리 사용 증가
- **제한**: MySQL `max_allowed_packet` 설정 확인 필요 (기본값: 16MB)

#### `rate_limit_per_sec`
- **타입**: `float`
- **설명**: FDR API 호출 제한 (초당 최대 요청 수)
- **기본값**: `5`
- **이유**: Yahoo Finance API rate limit 준수 (차단 방지)
- **권장**: 변경 금지 (5 이하 유지)
- **사용처**: `core/rate_limiter.py`

#### `jitter`
- **타입**: `boolean`
- **설명**: Rate limiting 시 랜덤 지연 추가 여부
- **기본값**: `true`
- **효과**: API 요청 시간을 불규칙하게 분산 (차단 위험 감소)
- **권장**: 항상 `true`

#### `retry` (재시도 설정)
##### `max_attempts`
- **타입**: `integer`
- **설명**: API 호출 실패 시 최대 재시도 횟수
- **기본값**: `5`
- **예시**: 네트워크 오류 발생 시 5회까지 재시도

##### `backoff_base_sec`
- **타입**: `integer` (초)
- **설명**: 지수 백오프 기본 대기 시간
- **기본값**: `1`
- **동작**: 1차 재시도: 1초 대기, 2차: 2초, 3차: 4초, ...

##### `backoff_max_sec`
- **타입**: `integer` (초)
- **설명**: 재시도 대기 시간 최대 상한
- **기본값**: `30`
- **의미**: 아무리 많이 실패해도 30초 이상 대기하지 않음

## 3. markets (시장별 운영 시간 설정)

### 개요
각 거래소의 장 마감 시간 및 안전 버퍼 설정입니다.

### 설정값

#### `close_times`
- **타입**: `object` (키-값 쌍)
- **설명**: 거래소별 장 마감 시간 (24시간 형식)
- **기본값**:
  ```yaml
  close_times:
    XKRX: "16:00"   # 한국거래소
    NYSE: "16:00"   # 뉴욕증권거래소 (미국 동부 시간 기준)
  ```
- **사용처**: `daily_update.py`에서 장 마감 후 실행 체크
- **확장 예시**:
  ```yaml
  close_times:
    XKRX: "16:00"
    NYSE: "16:00"
    LSE: "16:30"   # 런던증권거래소
    TSE: "15:00"   # 도쿄증권거래소
  ```

#### `safe_delay_minutes`
- **타입**: `integer` (분)
- **설명**: 장 마감 후 데이터 안정화 대기 시간
- **기본값**: `30`
- **의미**: 장 마감 후 30분 이후에만 `daily_update.py` 실행 허용
- **이유**: 
  - 증권사 시스템 데이터 확정 시간 필요
  - Yahoo Finance API 데이터 업데이트 지연 고려
- **예시**: XKRX 16:00 마감 → 16:30 이후 실행 가능
- **우회**: `--force` 플래그로 무시 가능

## 4. indicators (지표 계산 및 저장 설정)

### 개요
기술적 지표 계산 파이프라인 및 DB 저장 방식 설정입니다.

### 4.1. materialization (저장 방식 설정)

#### `mode`
- **타입**: `string`
- **옵션**: `long` | `wide` | `none` | `hybrid`
- **기본값**: `long`
- **설명**:
  - `long`: EAV 패턴 (현재 사용) - `stock_indicators` 테이블에 (symbol, date, indicator, value) 형태로 저장
  - `wide`: 각 지표를 별도 컬럼으로 저장 (미구현)
  - `none`: DB 저장 안 함 (계산만)
  - `hybrid`: long + wide 동시 저장 (미구현)
- **현재 프로젝트**: `long` 모드만 사용 중

#### `table_long`
- **타입**: `string`
- **설명**: long 모드 사용 시 저장할 테이블 이름
- **기본값**: `stock_indicators`
- **권장**: 기본값 유지 (DB 스키마와 일치)

#### `attach_to_price.prefix`
- **타입**: `string`
- **설명**: wide 모드에서 지표 컬럼명 앞에 붙일 접두사 (현재 미사용)
- **기본값**: `ind_`
- **예시**: `ind_sma_5_close`, `ind_ema_12_close`

### 4.2. pipeline (지표 계산 파이프라인)

지표 계산 순서 및 파라미터를 정의합니다.

#### 기본 형식
```yaml
pipeline:
  - name: 지표이름
    params:
      window: 기간
      column: 적용컬럼
    save: true/false
```

#### 설정 예시
```yaml
pipeline:
  - name: sma
    params:
      window: 5
      column: close
    save: true
  - name: ema
    params:
      window: 12
      column: close
    save: true
```

#### 파라미터 설명

##### `name`
- **타입**: `string`
- **설명**: 계산할 지표 이름 (등록된 지표만 사용 가능)
- **사용 가능한 지표**:
  - `sma`: Simple Moving Average (단순 이동평균)
  - `ema`: Exponential Moving Average (지수 이동평균)
  - `rsi`: Relative Strength Index (미구현)
  - `macd`: MACD (미구현)
- **참고**: `indicators/common/` 디렉토리에 구현된 지표만 사용 가능

##### `params.window`
- **타입**: `integer`
- **설명**: 지표 계산 기간 (일 수)
- **예시**:
  - `window: 5` → 5일 이동평균
  - `window: 20` → 20일 이동평균
  - `window: 200` → 200일 이동평균 (장기)

##### `params.column`
- **타입**: `string`
- **설명**: 지표 계산에 사용할 가격 컬럼
- **옵션**: `open`, `high`, `low`, `close`, `volume`
- **일반적 사용**: `close` (종가 기준)

##### `save`
- **타입**: `boolean`
- **설명**: DB에 저장 여부
- **기본값**: `true`
- **용도**: 중간 계산용 지표는 `save: false` 설정 가능

#### 확장 예시 (4개 지표)

```yaml
pipeline:
  - name: sma
    params: { window: 5, column: close }
    save: true
  - name: sma
    params: { window: 20, column: close }
    save: true
  - name: ema
    params: { window: 12, column: close }
    save: true
  - name: ema
    params: { window: 26, column: close }
    save: true
```

### 4.3. warmup_override (Warmup 기간 설정)

#### 개요
지표 계산 시 필요한 과거 데이터(warmup) 기간을 지표별로 오버라이드합니다.

#### 설정 형식
```yaml
warmup_override:
  지표이름: 배수x_window 또는 고정값
```

#### 기본값
```yaml
warmup_override:
  ema: 5x_window
  rsi: 5x_window
```

#### 설명

##### `ema: 5x_window`
- **의미**: EMA 계산 시 `window` 파라미터의 5배만큼 과거 데이터 필요
- **예시**: `ema_12_close` → warmup = 12 × 5 = 60일
- **이유**: EMA는 과거 모든 값의 가중 평균이므로 충분한 warmup 필요

##### `rsi: 5x_window`
- **의미**: RSI 계산 시 5배 warmup
- **예시**: `rsi_14_close` → warmup = 14 × 5 = 70일

#### 사용처
- `daily_update.py`의 `process_symbol()` 함수
- `pipeline.warmup_days()` 호출 시 반환값 결정

## 5. resync (데이터 재동기화 설정)

### 개요
주가 데이터의 무결성 검증 및 재동기화 정책 설정 (현재 미구현, 향후 기능)

### 설정값

#### `enabled`
- **타입**: `boolean`
- **설명**: 재동기화 기능 활성화 여부
- **기본값**: `true`
- **현재 상태**: 미구현 (예약 설정)

#### `detect_split_threshold`
- **타입**: `float` (0-1 사이)
- **설명**: 주식 분할/병합 감지 임계값
- **기본값**: `0.6` (60%)
- **의미**: 전일 대비 60% 이상 가격 변동 시 분할 의심
- **예시**: 
  - 전일 종가: 100,000원
  - 금일 종가: 50,000원 (50% 하락)
  - → 분할 감지 → 과거 데이터 재수집

#### `monthly_full_check`
- **타입**: `boolean`
- **설명**: 월 1회 전체 데이터 검증 실행 여부
- **기본값**: `true`
- **용도**: 누락된 날짜, 이상값 등 정기 점검

#### `full_check_day`
- **타입**: `integer` (1-31)
- **설명**: 전체 검증 실행 날짜 (매월)
- **기본값**: `1` (매월 1일)
- **예시**: `5`로 설정 시 매월 5일에 전체 검증

## 트러블슈팅

### 문제 1: "database 설정이 필요합니다" 에러

**원인**: `settings.yaml` 파일이 없거나 `database` 섹션이 누락됨

**해결**:
```bash
# 파일 존재 확인
ls -l config/settings.yaml

# 내용 확인
grep -A5 "database:" config/settings.yaml
```

### 문제 2: DB 연결 실패

**원인**: `url`의 계정 정보 또는 호스트가 잘못됨

**해결**:
```bash
# MySQL 직접 접속 테스트
mysql -h 127.0.0.1 -u YOUR_DB_USER -pYOUR_DB_PASSWORD market

# URL 형식 확인
# 올바른 형식: mysql+pymysql://사용자:비밀번호@호스트:포트/DB명?charset=utf8mb4
```

### 문제 3: 지표 계산 안 됨

**원인**: `pipeline`에 지표가 정의되지 않음

**해결**:
```yaml
indicators:
  pipeline:
    - name: sma  # ✅ 최소 1개 이상 필요
      params: { window: 5, column: close }
      save: true
```

### 문제 4: Rate limit 초과

**원인**: `rate_limit_per_sec` 값이 너무 높거나 `thread_workers`가 너무 많음

**해결**:
```yaml
runtime:
  rate_limit_per_sec: 5  # ✅ 5 이하로 유지
  thread_workers: 4      # ✅ 줄이기
```
