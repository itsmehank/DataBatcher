### 최종 프로젝트 계획안(v4)

본 계획안은 v1·v2·v3 문서를 통합하고, 운영 단계에서의 핵심 리스크(수정주가 이벤트, 지표 경계 왜곡, 티커 자동화, DB/레이트리밋 안정성)와 관측 가능성(Observability)을 보완하여 실무 투입이 가능한 수준으로 정리한 최종안입니다.

---

### 1) 목표와 원칙
- 목표: FDR 기반 멀티마켓(한국/미국/크립토) 가격 수집과 모듈형 지표 생성·저장을 안정적으로 운영. 데이터 정합성·확장성·관측 가능성 확보.
- 원칙:
  - 멱등성: 가격 `(symbol,date)`·지표 `(symbol,date,indicator,params_hash)` 유니크 키 업서트.
  - 플러그인 지표: `BaseIndicator`/레지스트리/파이프라인으로 레고식 조합.
  - 설정 주도: 지표/저장전략/스케줄/레이트리밋/워밍업 등은 `settings.yaml` 외부화.
  - 관측 가능성: 구조화 로그 + 메트릭 + 헬스체크 테이블 기록.

---

### 2) 아키텍처 개요 및 폴더 구조
- 수집: `collectors/*` (FDR 등)
- 지표: `indicators/*` + `IndicatorPipeline`
- 저장: `savers/*` (가격/지표 long·wide·hybrid)
- 실행: `scripts/*` (init/daily/gap/resync/ticker_sync)
- 공통: `core/*` (DB, 캘린더, 로깅, 파라미터 해시, 레이트리밋/리트라이)
- 마이그레이션: `migrations/` (Alembic)

프로젝트 스캐폴딩은 단계별로 생성하며, 설정과 파이프라인 정의는 YAML 중심으로 관리합니다.

---

### 3) 데이터 모델(DDL 요약)
- 가격(주식): `stock_prices(symbol,date,open,high,low,close,adj_close,volume,currency,market,source,etl_loaded_at)`
  - PK `(symbol,date)`
- 가격(크립토): `crypto_prices(...)` (유사 구조, 정밀도 확장)
- 지표(Long): `stock_indicators(symbol,date,indicator,params_hash,value,market,source,etl_loaded_at)`
  - PK `(symbol,date,indicator,params_hash)`
- 종목 마스터: `symbol_master(symbol,market,name,status,first_date,last_date,updated_at)`
- 헬스체크 로그: `sync_log(job_name,market,symbol,start_time,end_time,rows_processed,status,message,created_at)`

---

### 4) 시간/캘린더/시간대 전략
- `pandas_market_calendars`로 장/휴장 판단, 마감+버퍼(`safe_delay_minutes`) 적용.
- 암호화폐는 일자 경계를 `UTC` 기준(설정 가능)으로 고정 권장.

---

### 5) 지표(Indicator) 모듈 전략
- `BaseIndicator`/`IndicatorRegistry`/`IndicatorPipeline` 채택.
- 워밍업: EMA/RSI 등은 보수적으로 `window*5` 이상. 월 1회 스냅샷 정합성 검증.
- 저장: `long|wide|none|hybrid` 설정으로 결정. `params_hash`로 공존·멱등성 확보.

---

### 6) ETL 워크플로우
1) 초기 적재 `init_load.py`: 종목 마스터 기반 전기간 수집 → 가격 저장 → 지표 파이프라인 → 저장.
2) 일일 갱신 `daily_update.py`: 마감+버퍼 후 당일 수집, `warmup_days()`만큼 되돌아가 지표 재계산.
3) 갭 보충 `gap_filler.py`: `MAX(date)`와 영업일 비교 후 누락 구간만 채움.
4) 재동기화 `resync_corporate_actions.py`: 분할/배당 이벤트 감지 시 과거 전체 재수집+지표 전량 재계산.

---

### 7) 티커 관리 자동화
- `ticker_sync.py`: `fdr.StockListing(...)` 기반으로 `symbol_master` 업서트(신규/상폐/변경) 후 대상 심볼 최신화.

---

### 8) 성능/안정성
- 배치 업서트 `chunksize`(1000~5000) 도입, 인덱스 영향 최소화.
- 레이트 리밋 + 지터(0.8~1.4 배 랜덤), 지수 백오프 리트라이.
- 스레드풀(5~10)과 연결풀 튜닝(SQLAlchemy `pool_pre_ping=True`).

---

### 9) 데이터 품질/정합성
- 가격 검증: `Open/High/Low/Close>0`, `Low<=High`, `Volume>=0`.
- 지표 검증: NaN 비율 임계 초과 시 저장 제외.
- 월 1회 스냅샷 vs 증분 결과 비교, 임계 초과 시 Resync 트리거.

---

### 10) 관측 가능성(Observability)
- 구조화 로그(JSON) + `sync_log` 기록.
- 갭 리포팅: gap_filler 이후 미충족 데이터 경고/알림.
- 선택: 프로메테우스 메트릭 익스포트.

---

### 11) 설정 샘플(`config/settings.yaml` 핵심 키)
```
runtime:
  timezone: Asia/Seoul
  thread_workers: 8
  batch_size: 2000
  rate_limit_per_sec: 5
  jitter: true
  retry: { max_attempts: 5, backoff_base_sec: 1, backoff_max_sec: 30 }
markets:
  close_times: { XKRX: "16:00", NYSE: "16:00" }
  safe_delay_minutes: 30
indicators:
  materialization: { mode: long, table_long: stock_indicators, attach_to_price: { prefix: ind_ } }
  pipeline:
    - { name: sma, params: { window: 5, column: close }, save: true }
    - { name: ema, params: { window: 12, column: close }, save: true }
  warmup_override: { ema: 5x_window, rsi: 5x_window }
resync:
  enabled: true
  detect_split_threshold: 0.6
  monthly_full_check: true
  full_check_day: 1
```

### 12) 테스트/CI-CD
- 유닛(컬렉터 모킹/지표 검증), 통합(E2E), 회귀(`params_hash`), Alembic 마이그레이션 검증.

---

### 13) 단계별 마일스톤(Phase)
- M1: DB 스키마/엔진/기본 수집(KRX) + daily_update POC
- M2: IndicatorPipeline 통합 + long 저장 + 워밍업 증분
- M3: ticker_sync + gap_filler + 관측 가능성(로그/헬스테이블)
- M4: resync_corporate_actions(감지+전량 재계산) + 월간 스냅샷 검증
- M5: 성능 최적화(chunksize, rate jitter, 멀티스레드 튜닝) + US/CRYPTO 확장
- M6: Airflow/Prefect DAG화 및 운영 가이드 정리

---

### 14) 이번 스프린트(1차 작업) 범위

- 코어 컴포넌트 초안 확인: `core/date_utils.py`, `core/db_manager.py`(예시 기준 리파인 계획).
