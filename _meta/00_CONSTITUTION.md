# 헌법 (Constitution)

> 이 문서는 프로젝트의 최상위 원칙을 정의한다.  
> 한 번 정한 후에는 가급적 변경하지 않는다.  
> 변경이 필요하다면 반드시 의사결정 로그(04_DECISIONS.md)에 사유를 남긴다.  
> 모든 작업(계획, 개발, 감사)은 이 문서를 최우선 기준으로 삼는다.

---

## 1. 프로젝트의 목적

미너비니(Mark Minervini) 트레이딩 방법론을 개인의 일상에 통합하기 위한 **반자동 트레이딩 보조 시스템**을 구축한다.

핵심은 "자동 거래 시스템"이 아니라 **"의사결정 보조 시스템"**이다. 시스템이 종목을 찾고, 분석하고, 제안한다. 사용자는 핵심 의사결정만 내린다. 일상적 작업은 시스템이, 책임 있는 결정은 사람이 한다.

## 2. 절대 원칙 (Inviolable Principles)

다음 원칙은 어떠한 경우에도 위배되어서는 안 된다. 위배 가능성이 발견되면 개발을 중단하고 재설계한다.

### 2.1 LLM은 절대 직접 주문을 실행하지 않는다

- LLM(에이전트 포함)은 분석·조언·제안만 한다.
- 실제 주문 실행은 결정론적 코드(if-then 규칙)만 담당한다.
- LLM의 출력이 주문으로 이어지는 모든 경로에는 **사용자 승인 게이트**가 반드시 존재한다.

### 2.2 결정론적 코어와 LLM 분석 레이어는 물리적으로 분리한다

- 데이터 적재, 인디케이터 계산, 템플릿 필터, 주문 실행, 포트폴리오 업데이트는 LLM이 호출되지 않는 코드로만 구현한다.
- LLM 분석 모듈은 별도 프로세스/모듈로 분리하고, 결정론적 코어는 LLM 모듈의 결과를 "데이터"로만 받는다.

### 2.3 검증되지 않은 LLM 판단으로 실거래하지 않는다

- 자동 주문 기능을 활성화하기 전, 반드시 백테스트로 LLM 판단의 과거 성과를 검증한다.
- 검증 기준: 승률, 평균 손익, 기대값, 최대 손실폭이 사전 정의된 임계값을 충족해야 한다.
- 임계값 미달 시 백테스트와 프롬프트 튜닝을 반복하며, 충족 전에는 자동 주문을 활성화하지 않는다.

### 2.4 페이퍼 트레이딩을 거치지 않은 자동 주문은 없다

- 자동 주문 엔진은 최소 4주간 페이퍼 트레이딩(가상 체결) 모드로 운영한 후 실거래로 전환한다.
- 실거래 전환 후에도 최초 2주 이상은 총자산의 5~10%만 할당해 운영한다.

### 2.5 모든 LLM 출력은 구조화된 형식으로 저장한다

- 자유 서술 텍스트가 아니라 JSON 스키마로 출력을 강제한다.
- 모든 LLM 호출과 응답은 DB 또는 로그에 영구 보존한다.
- 이는 사후 검증, 디버깅, 통계 분석을 위한 필수 조건이다.

### 2.6 안전 장치 없는 주문 엔진은 가동하지 않는다

자동 주문 엔진은 다음 안전 장치를 모두 갖춘 상태로만 가동한다:

- 1회 주문 최대 금액 제한
- 1일 주문 횟수 제한
- 중복 주문 방지
- 시스템 오류 시 자동 중단(circuit breaker)
- 모든 주문 시도의 영구 로그 기록

## 3. 설계 원칙 (Design Principles)

### 3.1 4계층 아키텍처를 유지한다

- 계층 1: 결정론적 코어 (데이터·필터·주문·포트폴리오)
- 계층 2: LLM 분석 (단발 호출 함수)
- 계층 3: 자동화 파이프라인 (엑셀·메일·UI)
- 계층 4: 에이전트 (대화형·도구 사용)

계층 간 의존성은 위에서 아래로만 흐른다. 하위 계층이 상위 계층을 직접 호출하지 않는다.

### 3.2 모듈은 인터페이스로 연결한다

- 각 모듈의 입출력은 GLOSSARY.md에 정의된 스키마를 따른다.
- 스키마 변경은 의사결정 로그에 기록한다.
- 인터페이스가 명확하면 모듈은 독립적으로 개발·교체될 수 있다.

### 3.3 점진적 구축, 단계별 가치

각 Phase는 독립적으로 가치를 가져야 한다. 즉, Phase 3에서 멈춰도 Phase 3까지 만든 것은 사용 가능한 형태여야 한다. "전부 다 만들어야 쓸 수 있는" 설계를 피한다.

## 4. 사용자가 절대 잃지 말아야 할 것

### 4.1 통제권

- 시스템이 사용자를 대신해 결정하지 않는다.
- 사용자는 언제든 모든 자동화를 일시 중단할 수 있어야 한다.
- 시스템의 모든 판단에 대해 사용자는 "왜?"를 물을 수 있어야 한다.

### 4.2 이해

- 시스템의 어떤 판단도 블랙박스여서는 안 된다.
- 진입 제안, 매도 권고, 비중 조정 권유 — 모두 근거를 제시해야 한다.
- 사용자가 시스템의 판단 로직을 이해하지 못하면 신뢰할 수 없고, 신뢰하지 못하면 따르지 않는다.

### 4.3 학습

- 시스템은 사용자가 미너비니 방법론을 더 깊이 이해하는 데 기여해야 한다.
- 단순히 신호를 주는 도구가 아니라, 왜 그 신호인지 설명하는 도구다.

## 5. 성공 기준 (Success Criteria)

이 프로젝트는 다음 조건이 충족되었을 때 "성공"으로 정의한다:

1. 매일 아침 미너비니 템플릿 통과 종목과 LLM 분석 결과가 자동으로 정리되어 사용자에게 전달된다.
2. 사용자는 대시보드에서 종목별 차트와 분석을 검토하고, 진입 결정을 내릴 수 있다.
3. 진입 결정 후 조건 감시·주문·손절은 시스템이 자동 처리한다.
4. 사용자는 시스템의 판단에 대해 자연어로 질의할 수 있고, 근거 있는 답을 받는다.
5. 시스템 운영에 사용자가 들이는 시간이 일평균 30~60분을 넘지 않는다.
6. 자동 주문 활성화 후 6개월 누적 성과가 KOSPI 또는 S&P 500 벤치마크 대비 양(positive)의 알파를 가진다.

## 6. 명시적 비목표 (Non-goals)

다음은 이 프로젝트의 목표가 아니다. 작업 중 이 방향으로 흐르려는 유혹이 있다면 의식적으로 거부한다.

- **고빈도 거래(HFT)**: 일봉 기반 스윙 트레이딩 시스템이다.
- **타인에게 판매하는 SaaS 제품**: 개인 사용을 위한 시스템이다.
- **모든 시장에서 작동하는 범용 시스템**: 미너비니 방법론과 KOSPI/KOSDAQ/NYSE/NASDAQ에 특화된다.
- **AI가 모든 것을 결정하는 자율 시스템**: 사용자의 통제권을 절대 양보하지 않는다.
- **수익 보장 시스템**: 어떤 시스템도 수익을 보장할 수 없으며, 이 시스템도 손실 가능성을 전제한다.
