# 로드맵 (Roadmap)

> 이 문서는 시스템 완성까지의 단계별 계획을 정의한다.  
> 각 Phase는 독립적으로 가치를 가지며, 어느 Phase에서 멈춰도 그 시점까지의 산출물은 사용 가능해야 한다.  
> Phase 종료 시점에 Architect가 회고하고 필요하면 후속 Phase를 갱신한다.

---

## 진행 원칙

1. **Phase는 순차적으로 진행한다.** 동시에 두 Phase를 진행하지 않는다.
2. **각 Phase는 명확한 종료 조건을 갖는다.** 종료 조건이 충족되어야 다음 Phase로 넘어간다.
3. **각 Phase 종료 시 감사를 받는다.** 감사 보고서가 통과되어야 다음 Phase 시작.
4. **위험한 Phase일수록 더 길게 관찰한다.** 특히 Phase 6(자동 주문)은 페이퍼 트레이딩 4주 이상.
5. **계획은 살아있는 문서다.** Phase가 끝날 때마다 이 로드맵을 갱신한다.

---

## Phase 0: 이미 완료됨

**상태**: ✅ 완료 (프로젝트 시작 시점)

**완료된 작업**:
- (1) 매일 배치로 일봉 데이터 적재
- (2) 인디케이터 계산
- (3) 미너비니 템플릿 필터링
- (4) 시각화를 위한 백엔드 + 프론트엔드 (기본 구조)

**산출물**:
- MySQL DB에 일봉·인디케이터·템플릿 통과 종목 데이터 적재됨
- 대시보드에서 종목 목록 및 차트 조회 가능

---

## Phase 1: LLM 분석 레이어 구축

**기간 추정**: 2~3주

**목표**: 템플릿 통과 종목에 대해 LLM이 자동으로 차트 분석을 수행하고, 진입 후보를 분류·파라미터화하는 모듈을 구축한다.

**작업 항목**: (5) 차트 분석·분류, (6) 진입 파라미터 산출

**산출물**:
- LLM 분석 결과의 JSON 스키마 (GLOSSARY.md에 정의)
- `daily_analysis` 테이블 설계 및 생성
- (5) 차트 분석 함수: 입력 → LLM 호출 → 구조화 출력 → DB 저장
- (6) 진입 파라미터 함수: (5)의 entry 판정 종목 대상
- 일일 배치 스크립트에 (5)(6) 추가
- 모든 LLM 호출의 영구 로그 (`llm_calls` 테이블)

**종료 조건**:
- 매일 배치가 (3) 직후 (5)(6)을 자동 실행한다.
- DB에 분석 결과가 구조화된 형태로 누적된다.
- 최소 일주일치 결과를 사용자가 직접 검토하고 품질이 납득 가능한 수준이다.

**리스크 / 주의 사항**:
- LLM 출력의 일관성 — temperature=0, JSON 스키마 강제 필수
- 비용 관리 — 캐싱, 호출 횟수 모니터링
- 프롬프트 튜닝에 시간이 가장 많이 들 것임 (구현보다 튜닝이 어려움)

---

## Phase 2: 일일 리포트 (엑셀 + 메일)

**기간 추정**: 3~5일

**목표**: Phase 1의 분석 결과를 매일 아침 사용자에게 자동 발송한다.

**작업 항목**: (7) 엑셀 + 메일 발송

**산출물**:
- 엑셀 템플릿 디자인 (진입 후보, 관찰, 보유 종목 시트)
- 엑셀 생성 함수 (openpyxl 기반)
- SMTP 발송 함수
- 일일 배치 cron에 추가

**종료 조건**:
- 매일 정해진 시각(예: 06:00)에 자동으로 메일이 발송된다.
- 사용자가 메일만 봐도 그날의 후보를 파악할 수 있다.

**가치**:
이 단계만 완성되어도 시스템은 충분히 실용적이다. 사용자는 매일 아침 메일을 보고 수동 매매를 결정할 수 있다.

---

## Phase 3: 대시보드 확장 — AI 카드와 액션 버튼

**기간 추정**: 1~2주

**목표**: 기존 대시보드에 LLM 분석 결과를 표시하고, 사용자가 의사결정을 내릴 수 있는 UI를 갖춘다.

**작업 항목**: (4) 확장

**산출물**:
- 종목 상세 페이지에 "AI 판단" 카드 추가
  - 분류, 근거, 진입 파라미터, 리스크 플래그 표시
- "질문하기" 버튼 (Phase 4에서 실제 연결, 지금은 placeholder)
- "진입 예약" 버튼 (Phase 6에서 실제 연결, 지금은 DB에 reservation 레코드만 생성)
- 모바일 반응형 확인

**종료 조건**:
- 대시보드에서 종목별 AI 판단을 한눈에 볼 수 있다.
- 모바일에서 접속 가능한 형태(외부 접속 설정 포함, Cloudflare Tunnel 또는 Tailscale)이다.

---

## Phase 4: Q&A 에이전트

**기간 추정**: 2~3주

**목표**: 사용자가 LLM 판단에 대해 자연어로 질의하고, 에이전트가 도구를 사용해 답하는 대화형 인터페이스를 구축한다.

**작업 항목**: (8) Q&A 에이전트

**산출물**:
- 읽기 전용 도구 세트 정의 (DB 조회, 분석 이력, 유사 패턴 검색, 지표 조회)
- Anthropic API tool use 기능으로 에이전트 구현
- 대시보드의 "질문하기" 버튼과 연결
- 대화 히스토리 저장

**종료 조건**:
- 사용자 질문에 도구를 사용한 근거 있는 답변이 나온다.
- 에이전트가 임의로 데이터를 변경하거나 주문을 시도하지 않음을 검증한다.

**중요**: 이 에이전트는 절대 SELECT 외의 DB 작업이나 외부 API 호출 권한을 가지지 않는다. 도구 함수 자체에서 격리한다.

---

## Phase 5: 백테스트 시스템

**기간 추정**: 2~3주

**목표**: Phase 1의 LLM 판단이 과거 데이터에서 실제로 의미 있는 성과를 보였는지 검증한다.

**작업 항목**: (백테스트, 헌법 §2.3에 따라 필수)

**산출물**:
- 백테스트 엔진 (과거 시점에서 그 시점의 데이터만으로 (5)(6) 재실행)
- 가상 매매 시뮬레이터 (진입가 도달 시 가상 진입, 손절선 이탈 시 가상 손절)
- 성과 지표 산출 (승률, 평균 손익, 기대값, 최대 손실폭, 샤프 비율 등)
- 섹터별·시장 국면별 분해 분석
- 결과 리포트 (대시보드 또는 별도 분석 페이지)

**종료 조건**:
- 최소 1년치 백테스트 결과가 산출된다.
- 결과가 사전 정의된 임계값을 충족한다 (예: 승률 ≥ 50%, 기대값 > 0, 평균 손실 ≤ 8%).
- 충족하지 못하면 Phase 1로 돌아가 프롬프트 또는 필터 재조정.

**중요**: 이 단계를 통과하지 못하면 Phase 6으로 진행하지 않는다. 헌법 §2.3 절대 원칙.

---

## Phase 6: 자동 주문 엔진

**기간 추정**: 3~4주 + 페이퍼 트레이딩 4주 이상

**목표**: 사용자가 승인한 진입 조건과 손절 조건을 시스템이 자동으로 감시·실행한다.

**작업 항목**: (9) 자동 주문 엔진, (10) 포트폴리오 업데이트

**진행 단계**:

### 6-1. 증권사 API 연결 + 페이퍼 트레이딩 모드 (1주 + 4주 관찰)
- 증권사 API 선정 (한국투자증권 KIS, 키움 등)
- API 연동 및 인증
- 가상 체결 모드 구현 (실제 주문 대신 DB에 가상 체결 기록)
- **최소 4주 페이퍼 트레이딩 후 다음 단계**

### 6-2. 안전 장치 구현 (1주)
헌법 §2.6의 모든 안전 장치 구현:
- 1회 주문 최대 금액 제한
- 1일 주문 횟수 제한
- 중복 주문 방지
- Circuit breaker (오류 시 자동 중단)
- 모든 주문 시도의 영구 로그
- 사용자 2차 승인 옵션

### 6-3. 소액 실거래 (2주 이상)
- 총 자산의 5~10%만 할당
- 모든 매매를 사용자가 직접 모니터링
- 이상 징후 발견 시 즉시 중단

### 6-4. 정상 운영 전환
- 위 단계가 모두 무사히 통과되어야 진입

**종료 조건**:
- 모든 안전 장치가 작동함을 검증.
- 소액 실거래에서 의도치 않은 주문이 0건.
- 체결 → 포트폴리오 업데이트가 정확히 동기화됨.

---

## Phase 7: 포트폴리오 매니저 에이전트

**기간 추정**: 1~2주

**목표**: 현재 포트폴리오 상태를 분석하고 미너비니 원칙에 따른 조언을 제공한다.

**작업 항목**: (11) 포트폴리오 매니저 에이전트

**전제 조건**: Phase 6 안정화 (실제 포트폴리오 데이터가 쌓여야 의미 있음)

**산출물**:
- 포트폴리오 분석 도구 세트 (스냅샷, 섹터 익스포저, 거래 이력, 리스크 지표)
- 에이전트 구현
- 대시보드의 조언 배너 + 액션 버튼
- 트리거 정책 (예: 신규 체결 시, 일 1회 정기 등)

**종료 조건**:
- 포트폴리오 변화 시 적절한 조언이 생성된다.
- 모든 액션은 사용자 승인 게이트를 통과해 (9)로 전달된다.

---

## Phase 8: 매매 통계 + 자기학습 루프

**기간 추정**: 1주 + 데이터 축적 (3개월 이상)

**목표**: 실거래 통계를 산출하고, 그 결과를 시스템 파라미터에 피드백한다.

**작업 항목**: (12) 매매 통계

**산출물**:
- 통계 집계 SQL/스크립트
- 주간 리포트 생성
- 통계 기반 파라미터 조정 제안 로직
- 대시보드의 "전략 업데이트" UI

**종료 조건**:
- 주간 리포트가 자동 생성된다.
- 통계 기반 제안이 사용자 승인 게이트를 통해 (3) 템플릿 필터에 반영 가능하다.

**주의**:
- 최소 100거래 이상 누적 후 통계 기반 조정을 시작한다 (소표본 함정 방지).
- 통계 결과의 자동 반영은 절대 금지. 항상 사용자 승인 필수.

## 누적 타임라인

| Phase | 기간       | 누적   | 주요 마일스톤                          |
| ----- | ---------- | ------ | -------------------------------------- |
| 0     | 완료       | -      | 데이터 코어 + 기본 대시보드             |
| 1     | 2~3주      | 3주    | LLM 분석 결과가 DB에 누적              |
| 2     | 3~5일      | 3.5주  | 매일 아침 메일 수신 시작               |
| 3     | 1~2주      | 5주    | 모바일에서 AI 판단 검토 가능           |
| 4     | 2~3주      | 7~8주  | 시스템과 자연어 대화 가능              |
| 5     | 2~3주      | 9~10주 | 백테스트 검증 완료, 자동매매 진입 준비 |
