# DataBatcher US 지수 주봉 테이블 실행 가이드

본 문서는 DataBatcher 프로젝트의 **미국 지수 주봉 테이블** 생성 및 업데이트 작업에 대한 실행 가이드입니다.

**최종 업데이트**: 2026-02-07

> **중요**: 주봉 가격/지표 모두 **INSERT ONLY**로 동작합니다.
> - 기존 row가 있으면 UPDATE하지 않고 PASS(멱등성 보장)
> - 목적: 이미 계산된 주봉/지표를 덮어써서 바뀌는 일을 방지

## 프로젝트 개요

US 지수 주봉 테이블은 US 지수 일봉 데이터(`us_index_prices`)를 주 단위로 집계하여 생성됩니다.

**핵심 파이프라인**: US 지수 일봉 데이터 조회 → 주봉 집계 → 주봉 지표 계산 → DB 저장

**대상 지수**: S&P 500 (US500), Dow Jones (DJI), NASDAQ Composite (IXIC)

**특이사항**: 지수는 3개뿐이므로 병렬 처리 없이 순차 처리합니다.

## 1. 사전 요구사항

### 필수 선행 작업

US 지수 주봉 테이블 작업을 시작하기 전에 **반드시** 다음 작업이 완료되어야 합니다:

1. **US 지수 마스터 동기화 완료**
   - `us_index_sync_master.py`로 지수 마스터가 동기화되어 있어야 함
   - `us_index_master` 테이블에 US500, DJI, IXIC 존재 필요

2. **US 지수 일봉 데이터 수집 완료**
   - `us_index_bulk_update.py`로 과거 US 지수 일봉 데이터가 수집되어 있어야 함
   - `us_index_prices` 테이블에 데이터 존재 필요

3. **데이터베이스 스키마 적용**
   - `us_index_prices_weekly`, `us_index_indicators_weekly` 테이블 존재 확인
   - 마이그레이션: `apps/ingest-databatcher/scripts/migrations/add_us_index_weekly_tables.sql`

4. **설정 파일 확인**
   - `apps/ingest-databatcher/config/settings.yaml`에 `indicators_us_index_weekly` 섹션 존재


## 3. 상세 실행 가이드

### Step 1: US 지수 일봉 데이터 존재 확인

```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBConfig, DBManager
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:
    r = conn.execute(text('SELECT symbol, COUNT(*), MIN(date), MAX(date) FROM us_index_prices GROUP BY symbol'))
    for row in r:
        print(row)
"
```

**예상 결과**:
```
('DJI', 1260, datetime.date(2020, 1, 2), datetime.date(2024, 12, 31))
('IXIC', 1260, datetime.date(2020, 1, 2), datetime.date(2024, 12, 31))
('US500', 1260, datetime.date(2020, 1, 2), datetime.date(2024, 12, 31))
```

### Step 2: 과거 주봉 데이터 일괄 생성 (Bulk Collection)

**목적**: 모든 US 지수의 과거 일봉 데이터를 주봉으로 집계

```bash
# 전체 US 지수, DB 전체 기간 주봉 생성 (가장 일반적)
python apps/ingest-databatcher/scripts/us_index_bulk_update_weekly.py

# 특정 기간만
python apps/ingest-databatcher/scripts/us_index_bulk_update_weekly.py --start 2020-01-01 --end 2024-12-31

# S&P 500만
python apps/ingest-databatcher/scripts/us_index_bulk_update_weekly.py --market SP500
```

**예상 소요 시간**: 1분 이내 (지수 3개, DB 조회만)

**예상 결과**: 각 지수당 약 52주/년 × 기간(년) 주봉 가격 + 지표(3개 × 주 수) 건

### Step 3: 주봉 증분 업데이트 테스트

```bash
# 전체 지수 업데이트
python apps/ingest-databatcher/scripts/us_index_weekly_update.py --all

# 특정 마켓만
python apps/ingest-databatcher/scripts/us_index_weekly_update.py --all --market SP500

# 특정 지수만

```

## 4. 정규 운영 방법

### 4.1. 주간 작업: US 지수 주봉 업데이트

**실행 주기**: 매주 토요일 (금요일 US 장마감 데이터 확정 후)

```bash
python apps/ingest-databatcher/scripts/us_index_weekly_update.py --all
```

**동작 방식**:
1. 최근 250주 일봉 데이터 조회 (us_index_prices)
2. 주봉으로 집계
3. 주봉 가격 저장: INSERT ONLY
4. 주봉 지표 계산 (warmup 포함)
5. 최신 주부터 역순 처리:
   - 모든 지표가 완료된 주 만나면 중단 (조기 종료)
   - 누락된 주만 지표 INSERT ONLY

**주봉 날짜 규칙**:
- `week_start`: 해당 주의 첫 거래일 (월요일 고정 아님)
- `week_end`: 해당 주의 마지막 거래일

**로그 해석 주의**:
- `주봉 가격 N건 처리(insert-only)`의 `N`은 처리 건수이며 실제 신규 삽입 건수와 다를 수 있습니다.

### 4.2. 일봉과 주봉의 실행 순서

```
[매일 평일 07:00 KST (16:00 ET + 30min 이후)]
us_index_daily_update.py --all --force
↓
[매주 토요일 10:00 KST]
us_index_weekly_update.py --all
```

## 6. 설정 시스템

### 6.1. 주봉 설정 위치

`apps/ingest-databatcher/config/settings.yaml`의 `indicators_us_index_weekly` 섹션:

```yaml
indicators_us_index_weekly:
  materialization:
    mode: long
    table_long: us_index_indicators_weekly
  pipeline:
    - name: sma
      params: { window: 5, column: close }   # 5주 (약 1개월)
      save: true
    - name: sma
      params: { window: 20, column: close }  # 20주 (약 5개월)
      save: true
    - name: sma
      params: { window: 40, column: close }  # 40주 (약 10개월)
      save: true
```

## 8. FAQ 및 트러블슈팅

### Q1. 주봉 데이터가 생성되지 않음

**원인**: US 지수 일봉 데이터가 없음

**확인**:
```sql
SELECT symbol, COUNT(*), MIN(date), MAX(date) FROM us_index_prices GROUP BY symbol;
```

**해결**:
```bash
# 먼저 US 지수 일봉 데이터 수집
python apps/ingest-databatcher/scripts/us_index_bulk_update.py --start 2020-01-01 --end 2024-12-31

# 그 다음 주봉 생성
python apps/ingest-databatcher/scripts/us_index_bulk_update_weekly.py
```

### Q2. 일봉과 주봉 데이터 일관성 검증

```sql
SELECT w.symbol, w.week_start, w.volume as weekly_vol,
       (SELECT SUM(volume) FROM us_index_prices d
        WHERE d.symbol = w.symbol AND d.date BETWEEN w.week_start AND w.week_end) as daily_sum
FROM us_index_prices_weekly w WHERE w.symbol = 'US500' LIMIT 5;
```

### Q3. 멱등성 확인

재실행 시 기존 데이터가 덮어써지지 않음을 확인:
```bash
# 첫 번째 실행
python apps/ingest-databatcher/scripts/us_index_weekly_update.py --all

# 두 번째 실행 - "모든 지표 완료 → 중단" 메시지가 나와야 함
python apps/ingest-databatcher/scripts/us_index_weekly_update.py --all
```

### Q4. 뷰를 이용한 주봉 + 이동평균 조회

```sql
SELECT * FROM v_us_index_price_weekly_with_ma
WHERE symbol = 'US500'
ORDER BY week_start DESC
LIMIT 10;
```

### Q5. 재실행 시에도 "주봉 가격 N건 처리(insert-only)"가 큼

정상 동작일 수 있습니다. `N`은 처리 건수이며, `INSERT IGNORE` 특성상 중복 키는 DB에서 무시됩니다.

**해석 방법**:
- 가격 로그는 처리량 지표로 확인
- 실제 신규 적재 여부는 최신 주 추가 여부/테이블 row 증가로 확인
