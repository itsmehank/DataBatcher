# DataBatcher 실행 가이드 (Crypto / Binance Spot)

본 문서는 DataBatcher 프로젝트에서 **Binance Spot(USDT) 코인 일봉 데이터**를 적재/업데이트하기 위한 단계별 안내서입니다.

**최종 업데이트**: 2026-02-03

> 본 문서는 **암호화폐(코인) 기능만** 다룹니다.
> - 주식/ETF 일봉 적재: `적재작업_가이드.md`
> - 주식/ETF 주봉 적재: `주봉테이블_작업가이드.md`

---

## 프로젝트 개요

DataBatcher의 코인 파이프라인은 주식 파이프라인과 유사한 운영 경험을 제공합니다.

**핵심 파이프라인**:

1) 심볼 마스터 동기화: `crypto_symbol_master`
2) 일봉 가격 적재: `crypto_prices_daily`
3) 일봉 지표 적재(long-form): `crypto_indicators_daily`

**데이터 범위(현재 고정)**
- Binance **Spot**
- **USDT 마켓** (예: BTCUSDT, ETHUSDT)
- **1d(일봉)**
- date 기준: **UTC**
- volume: **quote asset volume**(`volume_quote`) 사용

## 2. 최초 설치 및 실행 (Quick Start)

처음 시작하는 경우, 다음 4단계로 빠르게 시작할 수 있습니다.

**예상 소요 시간**: 5-10분

```bash
# 1) 가상환경 활성화 및 의존성 설치
source .venv/bin/activate
pip install -r requirements.txt

# 2) DB 준비 (Docker 사용 시)
cd docker && docker compose up -d && cd ..

# 3) DB 초기화(테이블 생성)
python apps/ingest-databatcher/scripts/init_db.py

# 4) 코인 심볼 마스터 적재(USDT spot 전체)
python apps/ingest-databatcher/scripts/crypto_sync_symbol_master.py --all

# 5) (테스트) BTCUSDT 1주 + 지표 적재
python apps/ingest-databatcher/scripts/crypto_bulk_update_daily.py --symbols BTCUSDT --start 2026-01-01 --end 2026-01-07 --with-indicators
```

## 3. 상세 실행 가이드

### Step 1: 설정 확인

`apps/ingest-databatcher/config/settings.yaml`의 코인 섹션을 확인합니다.

```yaml
crypto:
  exchange: BINANCE
  quote_asset: USDT
  timezone: UTC
  targets:
    # bulk/daily에서 --all/--symbols가 없을 때 기본으로 처리할 심볼 목록
    symbols: [BTCUSDT]

indicators_crypto_daily:
  materialization:
    mode: long
    table_long: crypto_indicators_daily
  pipeline:
    - name: sma
      params: { window: 5, column: close }
      save: true
    - name: sma
      params: { window: 20, column: close }
      save: true
    - name: sma
      params: { window: 40, column: close }
      save: true
```

> `crypto.targets.symbols`는 “기본 대상 심볼 목록”입니다.
> - `--symbols`를 주면 해당 심볼만 처리
> - `--all`을 주면 `crypto_symbol_master`의 ACTIVE 전부 처리

---

### Step 2: 코인 심볼 마스터 동기화

**목적**: Binance에서 Spot+TRADING+USDT 페어 목록을 가져와 `crypto_symbol_master`에 저장

```bash
python apps/ingest-databatcher/scripts/crypto_sync_symbol_master.py --all
```

테스트로 일부만 적재하려면:

```bash
python apps/ingest-databatcher/scripts/crypto_sync_symbol_master.py --symbols BTCUSDT ETHUSDT
```

---

### Step 3: 코인 일봉 과거 데이터 적재 (Bulk)

**목적**: 특정 기간의 가격/지표를 한 번에 적재

#### 3-1. 특정 심볼만(BTCUSDT, 1개월)

```bash
python apps/ingest-databatcher/scripts/crypto_bulk_update_daily.py --symbols BTCUSDT \
  --start 2026-01-01 --end 2026-01-31 --with-indicators
```

#### 3-2. 기본 대상 심볼(settings.yaml)만

```bash
python apps/ingest-databatcher/scripts/crypto_bulk_update_daily.py \
  --start 2026-01-01 --end 2026-01-31 --with-indicators
```

#### 3-3. 전체 심볼(주의: 시간이 오래 걸릴 수 있음)

```bash
python apps/ingest-databatcher/scripts/crypto_bulk_update_daily.py --all \
  --start 2026-01-01 --end 2026-01-31 --with-indicators
```

**저장 정책**
- 가격/지표 모두 **insert_only**
  - 같은 기간을 다시 실행해도 기존 데이터는 수정되지 않으며, 없는 데이터만 삽입됩니다.

---

### Step 4: 코인 일봉 일일 업데이트 (Daily)

**목적**: 최근 N일만 갱신(가격 insert_only + 지표 insert_only)

- 기본 동작(권장): **최근 50일** 범위를 대상으로 적재합니다.
- 기본 end date: **실행 시점 UTC 날짜 기준 “어제(UTC-1day)”**
  - 목적: “완결된 일봉(1d) 캔들”만 DB에 적재

> 참고(검증/정리 스크립트 기준일):
> - `apps/ingest-databatcher/scripts/tests/db_crypto_assert_counts.py --days N`
> - `apps/ingest-databatcher/scripts/tests/db_crypto_cleanup.py --days N`
> 위 스크립트들도 `crypto_daily_update.py`와 동일하게 **end=UTC 어제** 기준으로 기간을 계산합니다.
> (로컬 타임존 영향으로 날짜가 어긋나는 문제를 방지)

```bash
python apps/ingest-databatcher/scripts/crypto_daily_update.py --with-indicators
```

- 기본 대상은 `crypto.targets.symbols`
- `--symbols` 또는 `--all`로 대상 우선순위를 변경할 수 있습니다.
- 필요 시 end date를 직접 지정할 수 있습니다(UTC date 기준):

```bash
python apps/ingest-databatcher/scripts/crypto_daily_update.py --end 2026-02-02 --with-indicators
```

## 4. 정규 운영 방법

권장 운영 흐름:

1) (주 1회) 심볼 마스터 동기화
```bash
python apps/ingest-databatcher/scripts/crypto_sync_symbol_master.py --all
```

2) (최초 1회) 과거 데이터 bulk 적재
```bash

  --start 2020-01-01 --end 2026-01-31 --with-indicators
```

3) (매일) 최근 데이터 daily 업데이트
```bash
python apps/ingest-databatcher/scripts/crypto_daily_update.py --with-indicators
```

## 5. 설정 시스템

### 5.1. 대상 심볼 선택 우선순위(암호화폐)

코인 bulk/daily는 아래 규칙으로 **처리 대상 심볼**을 결정합니다.

1. `--all`: `crypto_symbol_master`의 `status='ACTIVE'` 전체
2. `--symbols ...`: 해당 심볼만
3. default: `apps/ingest-databatcher/config/settings.yaml`의 `crypto.targets.symbols`

3번까지 갔는데도 대상이 비어 있으면 에러로 종료합니다.

### 5.2. 지표 설정

코인 일봉 지표는 `indicators_crypto_daily.pipeline`에 정의합니다.
- 현재 기본: `SMA(5)`, `SMA(20)`, `SMA(40)`

## 6. 자동화 설정

### 6.1. Cron 예시(Linux/Mac)

```bash
# crontab -e

# (매일) 코인 일봉 갱신
0 3 * * * cd /path/to/DataBatcher && source .venv/bin/activate && python apps/ingest-databatcher/scripts/crypto_daily_update.py --with-indicators >> logs/crypto_daily_update.log 2>&1

# (주 1회) 심볼 마스터 갱신
0 4 * * 0 cd /path/to/DataBatcher && source .venv/bin/activate && python apps/ingest-databatcher/scripts/crypto_sync_symbol_master.py --all >> logs/crypto_sync_symbol_master.log 2>&1
```

> 시간대: date 기준은 UTC지만, 스케줄 실행 시각은 서버(로컬) 타임존을 따릅니다.

## 7. FAQ 및 트러블슈팅

### Q1. `nan can not be used with MySQL` 에러가 발생합니다

- 원인: 지표의 warmup 구간에서 NaN 발생
- 현재 프로젝트에서는 DB 저장 전에 NaN/inf를 자동으로 NULL로 치환하도록 처리되어 있어야 합니다.
- 만약 재발한다면:
  - `core/db_manager.py`의 NaN 치환 로직 반영 여부를 확인하세요.

### Q2. 기존에 `--days 7`인데 왜 8일치가 적재되나요?

- (이전 버전) `--days N`은 “end_date 포함”으로 범위를 잡았습니다.
- 현재 버전은 `--days` 옵션이 제거되었고, **최근 50일(고정)** 범위를 사용합니다.

### Q3. 어떤 심볼이 적재되는지 헷갈립니다

- 스크립트 첫 줄에 `targets=... source=...`가 출력됩니다.
  - `source=--symbols`면 CLI 지정 심볼만
  - `source=--all ...`이면 전체
  - `source=config: crypto.targets.symbols`이면 settings 기반
