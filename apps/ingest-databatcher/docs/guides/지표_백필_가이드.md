## 1. 개요

### 문제

기존 파이프라인(`daily_update.py`, `bulk_update.py`)은 **가격 수집 + 지표 계산**이 결합되어 있습니다. 새 지표(예: SMA 200)를 추가하면:

- 가격 데이터를 다시 수집해야 함 (불필요한 API 호출)
- 기존 지표도 재계산됨 (중복 작업)
- 전체 종목 재실행 시 수십 분 소요

### 해결

`backfill_indicators.py`는 **DB에 이미 적재된 가격 데이터**만 읽어서 지표를 계산합니다:

- API 호출 없음 (DB 로컬 읽기만)
- 기존 지표와 독립적으로 관리 가능
- `insert_only` 모드로 기존 데이터 보존
- 병렬 처리 지원

---

## 2. 사전 요구사항

- 가격 데이터가 DB에 적재되어 있어야 합니다
  - 한국 주식: `stock_prices` 테이블
  - 미국 주식: `us_stock_prices` 테이블
- `symbol_master` / `us_symbol_master` 테이블에 종목 정보가 있어야 합니다

> 가격 데이터가 없는 상태에서 실행하면 "No price data in DB" 에러가 발생합니다.

## 3. 설정 방법

### config/settings.yaml

백필 전용 설정 섹션이 별도로 존재합니다:

```yaml
# 한국 주식 지표 백필 전용
indicators_backfill:
  materialization:
    mode: long
    table_long: stock_indicators
  pipeline:
    - name: sma
      params: { window: 50, column: close }
      save: true
    - name: sma
      params: { window: 100, column: close }
      save: true
    # 새 지표는 여기에 추가

# 미국 주식 지표 백필 전용
indicators_us_backfill:
  materialization:
    mode: long
    table_long: us_stock_indicators
  pipeline:
    - name: sma
      params: { window: 50, column: close }
      save: true
    # ...
```

> 기존 `indicators` / `indicators_us` 섹션과 **별도**이므로, 일일 업데이트 파이프라인에 영향 없이 관리할 수 있습니다.

## 4. 실행 방법

### 기본 사용법

```bash
# 한국 주식 전체
python scripts/backfill_indicators.py --source stock_prices

# 미국 주식 전체
python scripts/backfill_indicators.py --source us_stock_prices
```

### CLI 옵션

| 인자 | 필수 | 기본값 | 설명 |
|------|------|--------|------|
| `--source` | O | - | `stock_prices` 또는 `us_stock_prices` |
| `--market` | X | ALL | 시장 필터 (KR: KOSPI/KOSDAQ/KONEX/ETF, US: NYSE/NASDAQ/ETF) |
| `--symbols` | X | - | 종목 코드 목록 (`--market`보다 우선) |
| `--workers` | X | 4 | 병렬 워커 수 |
| `--mode` | X | insert_only | 저장 모드 (`insert_only` / `upsert`) |

### 실행 예시

```bash
# KOSPI만 백필
python scripts/backfill_indicators.py --source stock_prices --market KOSPI

# 특정 종목만
python scripts/backfill_indicators.py --source stock_prices --symbols 005930 000660

# NASDAQ 미국 주식, 병렬 8개
python scripts/backfill_indicators.py --source us_stock_prices --market NASDAQ --workers 8

# 기존 지표 덮어쓰기 (재계산)
python scripts/backfill_indicators.py --source stock_prices --mode upsert
```

### 저장 모드 설명

- **insert_only** (기본): 이미 존재하는 지표는 스킵, 새 지표만 추가
  - 동일 명령 2회 실행해도 중복 적재 없음 (안전)
  - 새 지표 추가 시 권장
- **upsert**: 기존 지표 값을 새 값으로 덮어쓰기
  - 지표 계산 로직이 변경되어 재계산이 필요할 때 사용

### DATABASE_URL 오버라이드

테스트 DB에서 실행하려면:

```bash
DATABASE_URL="mysql+pymysql://user:pass@host:3306/trade_test?charset=utf8mb4" \
  python scripts/backfill_indicators.py --source stock_prices --symbols 005930
```

## 5. 새 지표 추가 워크플로우

새 지표를 추가하고 과거 데이터에 백필하는 전체 흐름입니다.

### Step 1: 지표 구현

```python
# indicators/common/rsi.py
from indicators.registry import IndicatorRegistry
from indicators.base_indicator import BaseIndicator, IndicatorParams

@IndicatorRegistry.register
class RSI(BaseIndicator):
    name = "rsi"
    def required_columns(self, p): return ["close"]
    def warmup(self, p): return int(p.params.get("window", 14)) * 2
    def compute(self, df, p):
        # RSI 계산 로직
        pass
```

### Step 2: Import 등록

`scripts/backfill_indicators.py` 상단에 추가:

```python
from indicators.common import rsi as _reg_rsi  # noqa: F401
```

### Step 3: 백필 설정에 추가

`config/settings.yaml`의 `indicators_backfill.pipeline`에 추가:

```yaml
indicators_backfill:
  pipeline:
    # ... 기존 SMA ...
    - name: rsi
      params: { window: 14, column: close }
      save: true
```

### Step 4: 백필 실행

```bash
# insert_only 모드로 실행 → 기존 SMA는 스킵, 새 RSI만 추가
python scripts/backfill_indicators.py --source stock_prices
```

### Step 5: 일일 파이프라인에도 추가 (선택)

향후 일일 업데이트에서도 계산되게 하려면 `indicators.pipeline`에도 추가합니다.

## 6. 지원하는 지표 유형

### Per-symbol 지표 (이 스크립트로 처리)

`@IndicatorRegistry.register`로 등록된 지표:

| 지표 | 파일 | 설명 |
|------|------|------|
| SMA | `indicators/common/sma.py` | 단순이동평균 |
| EMA | `indicators/common/ema.py` | 지수이동평균 |

> 향후 RSI, MACD 등이 추가되면 registry에 등록 + yaml에 추가만으로 백필 가능

### Cross-sectional 지표 (별도 스크립트)

전 종목 횡단면 계산이 필요한 지표는 **이 스크립트의 범위 밖**입니다:

| 지표 | 스크립트 |
|------|----------|
| IBD RS Rating | `scripts/kr_rs_update.py` / `scripts/us_rs_update.py` |
| RS Line | `scripts/kr_rs_update.py` / `scripts/us_rs_update.py` |
| Blue Dot | `scripts/kr_rs_update.py` / `scripts/us_rs_update.py` |

## 7. FAQ / 트러블슈팅

### Q: 실패한 종목은 어떻게 확인하나요?

실패한 종목은 `logs/backfill_indicators_failed.log`에 기록됩니다.

```bash
cat logs/backfill_indicators_failed.log
```

### Q: 이미 존재하는 지표를 재계산하려면?

`--mode upsert`를 사용합니다:

```bash
python scripts/backfill_indicators.py --source stock_prices --mode upsert
```

### Q: 'Config section not found' 에러가 나옵니다

`config/settings.yaml`에 `indicators_backfill` 또는 `indicators_us_backfill` 섹션이 없는 경우입니다. 해당 섹션을 추가하세요.

### Q: 'No price data in DB' 에러가 나옵니다

해당 종목의 가격 데이터가 DB에 없습니다. 먼저 가격 수집을 실행하세요:

```bash
# 한국 주식
python scripts/bulk_update.py --start 2024-01-01 --end 2024-12-31

# 미국 주식
python scripts/us_bulk_update.py --start 2024-01-01 --end 2024-12-31
```

### Q: 일일 업데이트 파이프라인과 충돌하나요?

아니요. 백필 설정(`indicators_backfill`)과 일일 설정(`indicators`)은 별도 섹션이므로 독립적으로 관리됩니다. 다만, 동일한 지표 테이블에 저장하므로 `insert_only` 모드 사용 시 기존 데이터가 보존됩니다.

### Q: workers 수는 어떻게 설정하나요?

DB 로컬 읽기만 수행하므로 API rate limit 걱정이 없습니다. 일반적으로:

- `--workers 4`: 안정적 (기본값)
- `--workers 8`: 빠름
- `--workers 16`: CPU/DB 연결 수 여유 시
