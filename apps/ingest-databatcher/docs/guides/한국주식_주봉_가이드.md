# DataBatcher 주봉 테이블 실행 가이드

본 문서는 DataBatcher 프로젝트의 **주봉 테이블** 생성 및 업데이트 작업에 대한 실행 가이드입니다.

 **최종 업데이트**: 2026-01-28 (bulk_update_weekly.py 사용성 개선)

> 2026-02 업데이트(중요): **weekly_update도 가격/지표 모두 INSERT ONLY로 동작**합니다.
> - 기존 row가 있으면 UPDATE하지 않고 PASS(멱등성 보장)
> - 목적: 이미 계산된 주봉/지표를 덮어써서 바뀌는 일을 방지

**주요 변경 사항 (v2)**:
- `--start`, `--end` 파라미터 선택화: 미입력 시 DB 전체 기간 자동 조회
- `--market` 파라미터 기본값 "ALL" 제공: 전체 마켓이 기본 동작
- 더 간편한 실행: `python apps/ingest-databatcher/scripts/bulk_update_weekly.py`만으로 전체 처리 가능

## 프로젝트 개요

주봉 테이블은 일봉 데이터를 주 단위로 집계하여 생성됩니다.

**핵심 파이프라인**: 일봉 데이터 조회 → 주봉 집계 → 주봉 지표 계산 → DB 저장

## 1. 사전 요구사항

### 필수 선행 작업

주봉 테이블 작업을 시작하기 전에 **반드시** 다음 작업이 완료되어야 합니다:

1. **일봉 데이터 수집 완료**
   - `bulk_update.py`로 과거 일봉 데이터가 수집되어 있어야 함
   - `stock_prices` 테이블에 데이터 존재 필요

2. **데이터베이스 스키마 적용**
   - `python apps/ingest-databatcher/scripts/init_db.py` 실행으로 주봉 테이블 생성 완료
   - `stock_prices_weekly`, `stock_indicators_weekly` 테이블 존재 확인

3. **설정 파일 확인**
   - `apps/ingest-databatcher/config/settings.yaml`에 `indicators_weekly` 섹션 존재

## 4. 정규 운영 방법

### 4.1. 주간 작업: 주봉 업데이트

**실행 주기**: 매주 토요일 새벽 (금요일 장마감 데이터 확정 후)

```bash
# 전체 종목 주봉 업데이트
python apps/ingest-databatcher/scripts/weekly_update.py --all
```

**동작 방식**:
 1. 최근 250주(약 1750일) 일봉 데이터 조회
 2. 주봉으로 집계
- 3. 주봉 가격 저장: INSERT ONLY
 4. 주봉 지표 계산 (warmup 포함)
 5. 최신 주부터 역순 처리:
    - 모든 지표가 완료된 주 만나면 중단 (조기 종료)
    - 누락된 주만 지표 INSERT ONLY

**완결된 주만 적재(최신 주 스킵 정책)**
- 기본값: 실행 시점 기준 "가장 최신 주"는 **미완결 가능성이 있으므로 주봉 생성/저장을 스킵**합니다.
- 예외: KST 기준 토/일(주말)에는, 금요일 일봉 적재가 완료되었다는 전제하에 최신 주를 스킵하지 않고 포함할 수 있습니다.

**왜 토요일 새벽인가?**
- 금요일 장마감 데이터가 `daily_update.py`로 이미 수집됨
- 주말에 실행하여 서버 부하 분산
- 일주일 데이터가 완전히 확정된 시점

---

### 4.2. 일봉과 주봉의 실행 순서

#### 올바른 실행 순서

```
[매일 평일 17:00] 
daily_update.py --all --force
↓
[매주 토요일 02:00]
weekly_update.py --all
```

#### 의존성 관계

- **주봉은 일봉에 의존**: 일봉 데이터가 먼저 수집되어야 주봉 생성 가능
- **자동 보장**: 토요일 새벽에 실행하면 금요일 일봉이 이미 수집된 상태

---

### 4.3. 재수집 (Backfill)

특정 기간의 주봉 데이터를 다시 생성해야 하는 경우:

```bash
# 전체 마켓, DB 전체 기간 재생성
python apps/ingest-databatcher/scripts/bulk_update_weekly.py

# 전체 마켓, 특정 기간만 재생성
python apps/ingest-databatcher/scripts/bulk_update_weekly.py --start 2023-01-01 --end 2023-12-31

# KOSPI만, DB 전체 기간 재생성
python apps/ingest-databatcher/scripts/bulk_update_weekly.py --market KOSPI

# 특정 종목만 재생성
python apps/ingest-databatcher/scripts/weekly_update.py --symbols 005930 000660
```

**참고**:
- `bulk_update_weekly.py`는 **INSERT ONLY 모드**로 동작 (기존 데이터 보존)
- `weekly_update.py`도 **INSERT ONLY 모드**로 동작 (기존 데이터 보존)
- `--start`, `--end` 생략 시 DB의 전체 일봉 데이터 기간을 자동 조회
- `--market` 생략 시 기본값 "ALL" 적용 (전체 마켓)

## 5. 코드 기준 진실 소스(SoT)

문서와 코드가 다를 때는 아래 코드를 기준으로 판단합니다.

- 주봉 집계 규칙(week_start/week_end, 최신주 스킵): `core/weekly_aggregation.py`
- 한국 주식 주봉 증분 업데이트: `apps/ingest-databatcher/scripts/weekly_update.py`
- 한국 주식 주봉 벌크 생성: `apps/ingest-databatcher/scripts/bulk_update_weekly.py`

**핵심 규칙 요약**
- `week_start`는 월요일 고정이 아니라 **해당 주의 첫 거래일**입니다.
- `week_end`는 **해당 주의 마지막 거래일**입니다.
- `weekly_update.py`와 `bulk_update_weekly.py`는 모두 가격/지표 저장 시 **INSERT ONLY** 정책입니다.

## 6. 설정 시스템

### 6.1. 주봉 설정 위치

주봉 지표 설정은 `apps/ingest-databatcher/config/settings.yaml`의 `indicators_weekly` 섹션에 정의됩니다.

```yaml
# apps/ingest-databatcher/config/settings.yaml

# 일봉 설정 (기존)
indicators:
  pipeline:
    - name: sma
      params: { window: 5, column: close }
      save: true
    # ...

# 주봉 설정 (추가)
indicators_weekly:
  materialization:
    mode: long
    table_long: stock_indicators_weekly
  pipeline:
    - name: sma
      params: { window: 20, column: close }  # 20주 (약 5개월)
      save: true
    - name: sma
      params: { window: 50, column: close }  # 50주 (약 1년)
      save: true
    - name: sma
      params: { window: 100, column: close } # 100주 (약 2년)
      save: true
    - name: sma
      params: { window: 200, column: close } # 200주 (약 4년)
      save: true
    - name: ema
      params: { window: 21, column: close }
      save: true
  warmup_override:
    ema: 10x_window
    rsi: 5x_window
```

### 6.2. 주봉 지표 권장 설정

**장기 투자 관점의 주봉 지표**:

- **SMA(20)**: 약 5개월 (분기 단위)
- **SMA(50)**: 약 1년 (연간 추세)
- **SMA(100)**: 약 2년 (중장기 추세)
- **SMA(200)**: 약 4년 (초장기 추세)

**단기 트레이딩에는 일봉 지표 사용 권장**

### Q2. 주봉 날짜 형식 확인

**확인**:
```bash
mysql -h 127.0.0.1 -u YOUR_DB_USER -pYOUR_DB_PASSWORD market -e "
  SELECT week_start, week_end 
  FROM stock_prices_weekly 
  WHERE symbol = '005930' 
  LIMIT 3;"
```

**예상 결과** (yyyy-mm-dd 형식):
```
+------------+------------+
| week_start | week_end   |
+------------+------------+
| 2024-12-23 | 2024-12-27 |
| 2024-12-16 | 2024-12-20 |
| 2024-12-09 | 2024-12-13 |
+------------+------------+
```

참고: `week_start`는 월요일 고정이 아니라 해당 주의 **첫 거래일**입니다.
휴장 주에는 목요일/금요일이 `week_start`가 될 수 있습니다.

### Q3. 일봉과 주봉 데이터 일관성 검증

```bash
    w.week_start,

       AND d.date >= w.week_start
```

## 10. 데이터 검증 쿼리

### 9.1. 주봉 데이터 전체 확인

```sql
-- 주봉 가격 통계
SELECT 
  COUNT(DISTINCT symbol) as symbols,
  COUNT(*) as weekly_rows,
  MIN(week_start) as oldest_week,
  MAX(week_start) as newest_week
FROM stock_prices_weekly;

-- 주봉 지표 통계
SELECT 
  indicator,
  COUNT(*) as rows,
  COUNT(DISTINCT symbol) as symbols
FROM stock_indicators_weekly
GROUP BY indicator
ORDER BY indicator;
```

### 9.2. 특정 종목 주봉 상세

```sql
-- 삼성전자 최근 10주 주봉
SELECT 
  week_start,
  week_end,
  open,
  high,
  low,
  close,
  volume
FROM stock_prices_weekly
WHERE symbol = '005930'
ORDER BY week_start DESC
LIMIT 10;

-- 삼성전자 주봉 지표
SELECT 
  week_start,
  indicator,
  value
FROM stock_indicators_weekly
WHERE symbol = '005930'
  AND week_start >= DATE_SUB(CURDATE(), INTERVAL 12 WEEK)
ORDER BY week_start DESC, indicator;
```

### 9.3. 일봉-주봉 비교 View

```sql
-- 금요일 종가 비교
SELECT 
  d.symbol,
  d.date as friday_date,
  d.close as daily_close,
  w.week_start,
  w.week_end,
  w.close as weekly_close,
  ABS(d.close - w.close) as diff
FROM stock_prices d
JOIN stock_prices_weekly w 
  ON d.symbol = w.symbol 
  AND d.date = w.week_end
WHERE d.symbol = '005930'
ORDER BY d.date DESC
LIMIT 10;
```
