# DataBatcher 실행 가이드 (한국 주식시장 지수)

본 문서는 한국 주식시장 지수(KOSPI, KOSDAQ) 데이터를 수집하고 기술적 지표를 계산하여 DB에 적재하는 방법을 안내합니다.

**최종 업데이트**: 2026-02-06

## 개요

한국 주식시장 지수 파이프라인은 KOSPI(1001)와 KOSDAQ(2001) 대표 지수의 일봉 OHLCV 데이터를 pykrx API로 수집하고, 기술적 지표(SMA/EMA)를 계산하여 별도 테이블에 적재합니다.

**핵심 파이프라인**: 마스터 동기화 → 과거 데이터 수집(Bulk) → 일일 업데이트(Daily)

**주요 특징**:
- 개별 주식과 별도의 테이블 사용 (`kr_index_master`, `kr_index_prices`, `kr_index_indicators`)
- 지수는 수정주가(`adj_close`)가 없음
- 대상 지수가 2개뿐이므로 병렬 처리 없이 순차 처리

## 3. 상세 실행 가이드

### Step 1: 지수 마스터 동기화

**목적**: KOSPI(1001), KOSDAQ(2001) 지수 정보를 `kr_index_master` 테이블에 등록

```bash
python apps/ingest-databatcher/scripts/kr_index_sync_master.py
```

**예상 결과**:
```
[2026-02-06 22:48:10] Sync completed!
  Added: 2
  Updated: 0
  Duration: 6.2s
```

**등록되는 지수**:

| symbol | market | name |
|--------|--------|------|
| 1001 | KOSPI | 코스피 |
| 2001 | KOSDAQ | 코스닥 |

**확인 방법**:
```bash
python -c "
from core.config_loader import load_settings

from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
```

### Step 2: 과거 데이터 대량 수집 (Bulk Collection)

**목적**: 지정 기간의 지수 일봉 OHLCV + 기술적 지표를 일괄 수집

**주의**: `kr_index_sync_master.py`가 먼저 실행되어 있어야 합니다.

#### 실행 예시

```bash
# 2-1. 최근 1년 수집 (추천)

python apps/ingest-databatcher/scripts/kr_index_bulk_update.py --start 2020-01-01 --end 2024-12-31

# 2-3. KOSPI 지수만 수집
python apps/ingest-databatcher/scripts/kr_index_bulk_update.py --start 2024-01-01 --end 2024-12-31 --market KOSPI

# 2-4. KOSDAQ 지수만 수집
python apps/ingest-databatcher/scripts/kr_index_bulk_update.py --start 2024-01-01 --end 2024-12-31 --market KOSDAQ
```

#### CLI 옵션

| 옵션 | 필수 | 설명 | 기본값 |

| `--end` | O | 수집 종료일 (YYYY-MM-DD) | - |
| `--market` | X | KOSPI / KOSDAQ / ALL | ALL |

#### 예상 소요 시간

|------|----------|
| 1개월 | 5-10초 |
| 1년 | 10-20초 |

> 지수는 2개뿐이므로 개별 주식 수집보다 훨씬 빠릅니다.

#### 수집 결과 확인

```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBManager, DBConfig
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:
    # 가격 데이터 확인
    result = conn.execute(text('''
        SELECT symbol, COUNT(*) as cnt, MIN(date) as oldest, MAX(date) as newest
        FROM kr_index_prices GROUP BY symbol
    '''))
    print('=== 가격 데이터 ===')
    for row in result:
        print(f'  {row[0]}: {row[1]}건 ({row[2]} ~ {row[3]})')

    # 지표 데이터 확인
    result = conn.execute(text('''
        SELECT symbol, indicator, COUNT(*) as cnt
        FROM kr_index_indicators GROUP BY symbol, indicator
    '''))
    print('\\n=== 지표 데이터 ===')
    for row in result:
        print(f'  {row[0]} | {row[1]}: {row[2]}건')
"
```

#### 데이터 저장 방식

- **가격**: `INSERT ONLY` (기존 데이터 보존, 중복 무시)
- **지표**: `INSERT ONLY` (기존 데이터 보존, 중복 무시)
- **NaN 처리**: warmup 기간 등으로 지표값이 계산 불가능한 경우 `NULL`로 저장 (`keep_nan=True`)
- **IndicatorChecker**: 없음 (bulk는 전 구간 일괄 처리이므로 break 로직 불필요)
- 재실행해도 기존 데이터를 덮어쓰지 않으므로 안전합니다.

### Step 3: 일일 업데이트

**목적**: 매일 장마감 후 최신 지수 데이터 및 지표를 증분 업데이트

```bash
# 3-1. 전체 지수 업데이트 (추천)
python apps/ingest-databatcher/scripts/kr_index_daily_update.py --all --force

# 3-2. KOSPI 지수만 업데이트
python apps/ingest-databatcher/scripts/kr_index_daily_update.py --all --market KOSPI --force

# 3-3. 특정 지수만 업데이트
python apps/ingest-databatcher/scripts/kr_index_daily_update.py --symbols 1001 --force

# 3-4. 특정 기준일 지정
python apps/ingest-databatcher/scripts/kr_index_daily_update.py --all --end 2024-12-31 --force
```

#### CLI 옵션

| 옵션 | 필수 | 설명 | 기본값 |
|------|------|------|--------|
| `--all` | △ | 모든 ACTIVE 지수 수집 | - |
| `--symbols` | △ | 특정 지수코드 리스트 | - |
| `--market` | X | KOSPI / KOSDAQ / ALL (`--all`과 함께 사용) | ALL |
| `--end` | X | 기준 종료일 (YYYY-MM-DD) | 마지막 영업일 |
| `--force` | X | 장마감/버퍼 체크 무시 | False |

> `--all` 또는 `--symbols` 중 하나는 반드시 지정해야 합니다.

#### 동작 방식

1. **가격 수집**: 최근 50일 가격 데이터를 pykrx에서 수집 → `INSERT ONLY`
2. **DB 조회**: DB에서 최근 250일 가격 데이터 로드
3. **지표 계산**: 250일치 전체에 대해 SMA/EMA 계산 (warmup 포함)
4. **역순 저장**: 최신 날짜부터 역순으로 처리
   - `IndicatorChecker`로 모든 지표가 이미 완료된 날짜를 만나면 **조기 중단**
   - 미완성 날짜만 `INSERT ONLY`로 저장

#### 예상 출력 (첫 실행)

```
Loaded 2 indices from kr_index_master (market=ALL)
1001: 가격 34건 처리(insert-only)
1001: 34개 날짜 처리, 지표 136건 저장
2001: 가격 34건 처리(insert-only)
2001: 34개 날짜 처리, 지표 136건 저장
```

#### 예상 출력 (재실행 - 이미 최신)

```
Loaded 2 indices from kr_index_master (market=ALL)
1001: 가격 34건 처리(insert-only)
1001: 2026-02-06 모든 지표 완료 → 중단
1001: 0개 날짜 처리, 지표 0건 저장
2001: 가격 34건 처리(insert-only)
2001: 2026-02-06 모든 지표 완료 → 중단
2001: 0개 날짜 처리, 지표 0건 저장
```

#### 데이터 저장 방식

- **가격**: `INSERT ONLY` (기존 데이터 보존)
- **지표**: `INSERT ONLY` (기존 데이터 보존)
- **NaN 처리**: warmup 기간 지표값은 `NULL`로 저장
- **IndicatorChecker**: 있음 (최신 날짜부터 역순으로 확인, 완료된 날짜 감지 시 조기 중단)
- **로그 해석 주의**: `가격 N건 처리(insert-only)`의 `N`은 처리 건수이며, 실제 신규 삽입 건수와 다를 수 있습니다.

## 4. 정규 운영 방법

### 4.1. 주간 작업: 지수 마스터 동기화

**실행 주기**: 매주 1회 (일요일 새벽 권장)

```bash
python apps/ingest-databatcher/scripts/kr_index_sync_master.py
```

> KOSPI/KOSDAQ 대표 지수는 변경될 가능성이 거의 없지만, 안전을 위해 주간 실행을 권장합니다.

### 4.2. 일일 작업: 데이터 업데이트

**실행 주기**: 매 영업일 장마감 30분 후 (평일 16:30 이후)

```bash
python apps/ingest-databatcher/scripts/kr_index_daily_update.py --all --force
```

> `--force` 없이 실행하면 XKRX 16:00 + 30분 버퍼 이후에만 동작합니다.

### 4.3. 재수집 (Backfill)

과거 누락 구간의 데이터를 채우려면 `kr_index_bulk_update.py`를 사용합니다.

```bash
# 특정 기간 재수집
python apps/ingest-databatcher/scripts/kr_index_bulk_update.py --start 2023-01-01 --end 2023-12-31
```

`INSERT ONLY`로 동작하므로 기존 데이터는 보존되고 없는 날짜만 추가됩니다.

## 6. DB 스키마

### 테이블 구조

#### kr_index_master (지수 마스터)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| symbol (PK) | VARCHAR(32) | 지수 코드 (1001, 2001) |
| market | VARCHAR(16) | KOSPI / KOSDAQ |
| name | VARCHAR(128) | 지수명 (코스피, 코스닥) |
| status | VARCHAR(16) | ACTIVE / INACTIVE |
| etl_loaded_at | TIMESTAMP | 최초 적재 시각 |
| updated_at | TIMESTAMP | 최종 업데이트 시각 |

#### kr_index_prices (지수 일봉 가격)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| symbol (PK) | VARCHAR(32) | 지수 코드 |
| date (PK) | DATE | 거래일 |
| open | DECIMAL(18,4) | 시가 |
| high | DECIMAL(18,4) | 고가 |
| low | DECIMAL(18,4) | 저가 |
| close | DECIMAL(18,4) | 종가 |
| volume | BIGINT | 거래량 |
| market | VARCHAR(16) | KOSPI / KOSDAQ |
| source | VARCHAR(16) | pykrx |
| etl_loaded_at | TIMESTAMP | 적재 시각 |

> **참고**: 개별 주식(`stock_prices`)과 달리 `adj_close` 컬럼이 없습니다. 지수는 수정주가 개념이 불필요합니다.

#### kr_index_indicators (지수 기술적 지표)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| symbol (PK) | VARCHAR(32) | 지수 코드 |
| date (PK) | DATE | 거래일 |
| indicator (PK) | VARCHAR(64) | 지표명 (sma_5_close 등) |
| params_hash (PK) | CHAR(40) | 파라미터 해시 (SHA1) |
| value | DECIMAL(28,10) | 지표값 (NULL 가능) |
| market | VARCHAR(16) | KOSPI / KOSDAQ |
| source | VARCHAR(16) | pykrx |
| etl_loaded_at | TIMESTAMP | 적재 시각 |

### 테이블 간 관계

```
kr_index_master (2건)
  └── kr_index_prices (symbol별 일봉 데이터)
  └── kr_index_indicators (symbol별 지표 데이터, long-form)
```

## 7. 설정

### 지표 파이프라인 설정 (`apps/ingest-databatcher/config/settings.yaml`)

```yaml
indicators_kr_index:
  materialization:
    mode: long
    table_long: kr_index_indicators
  pipeline:
    - name: sma
      params: { window: 5, column: close }
      save: true
    - name: sma
      params: { window: 20, column: close }
      save: true
    - name: ema
      params: { window: 12, column: close }
      save: true
    - name: ema
      params: { window: 26, column: close }
      save: true
```

**기본 지표 목록**:

| 지표 | 파라미터 | DB indicator 컬럼값 |
|------|----------|---------------------|
| SMA | window=5, column=close | sma_5_close |
| SMA | window=20, column=close | sma_20_close |
| EMA | window=12, column=close | ema_12_close |
| EMA | window=26, column=close | ema_26_close |

> 지표를 추가/변경하려면 `apps/ingest-databatcher/config/settings.yaml`의 `indicators_kr_index.pipeline` 섹션을 수정하세요.

## 8. 자동화 설정


### Q2. pykrx 지수 데이터 수집 실패

**원인**: 네트워크 문제 또는 pykrx/KRX 서비스 장애

**확인 방법**:
```bash
# pykrx 지수 API 직접 테스트
python apps/ingest-databatcher/scripts/probes/pykrx_index_probe.py --index 1001 --start 2024-01-01 --end 2024-01-31
```

**해결**: 잠시 후 재시도. pykrx는 KRX 공시 서비스를 사용하므로 일시적 장애가 있을 수 있습니다.

### Q3. 지표가 일부 NULL로 저장됨

**정상 동작입니다.** warmup 기간(예: SMA(20)은 최소 20일 필요)에 해당하는 날짜의 지표값은 계산이 불가능하므로 `NULL`로 저장됩니다.

**확인**:
```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBManager, DBConfig
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:

            COUNT(*) as total,
```

### Q4. bulk_update 후 daily_update 실행 시 "모든 지표 완료 → 중단"

**정상 동작입니다.** `bulk_update`로 이미 적재된 기간의 지표가 모두 존재하면, `daily_update`는 해당 날짜에서 조기 중단합니다. 새로운 거래일이 추가되었을 때만 신규 데이터가 저장됩니다.

---

### Q5. daily_update 재실행 시에도 "가격 N건 처리(insert-only)"가 크게 보입니다

**정상 동작일 수 있습니다.** 이 로그의 `N`은 collector가 처리한 건수이며, `insert_only` 특성상 중복 키는 DB에서 무시됩니다.

**해석 방법**:
- 가격 로그는 처리량 지표로 확인
- 실제 신규 적재 여부는 최신 거래일 추가 여부 또는 테이블 row 증가로 확인

### Q6. 개별 주식 데이터에 영향이 있나요?

**없습니다.** 지수 파이프라인은 완전히 별도의 테이블(`kr_index_*`)을 사용하므로, 기존 `stock_prices`/`stock_indicators`/`symbol_master` 테이블에는 영향이 없습니다.
