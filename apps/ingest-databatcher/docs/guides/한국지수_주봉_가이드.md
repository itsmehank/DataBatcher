# DataBatcher 실행 가이드 (한국 주식시장 지수 - 주봉)

본 문서는 한국 주식시장 지수(KOSPI, KOSDAQ)의 주봉 데이터를 생성하고 기술적 지표를 계산하여 DB에 적재하는 방법을 안내합니다.

**최종 업데이트**: 2026-02-07

## 개요

한국 지수 주봉 파이프라인은 이미 적재된 일봉 데이터(`kr_index_prices`)를 주 단위로 집계하여 `kr_index_prices_weekly` 테이블에 저장하고, 주봉 기반 기술적 지표를 `kr_index_indicators_weekly` 테이블에 적재합니다.

**핵심 파이프라인**: 일봉 데이터(DB) → 주봉 집계 → 지표 계산 → DB 저장

**주요 특징**:
- 일봉 파이프라인과 별도의 테이블 사용 (`kr_index_prices_weekly`, `kr_index_indicators_weekly`)
- 외부 API 호출 없이 DB의 일봉 데이터를 집계하여 생성
- 지수는 수정주가(`adj_close`)가 없음
- 대상 지수가 2개뿐이므로 병렬 처리 없이 순차 처리

**선행 조건**: 일봉 데이터가 먼저 적재되어 있어야 합니다 → [적재작업_가이드_한국지수.md](적재작업_가이드_한국지수.md) 참고

#### 수집 결과 확인

```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBManager, DBConfig
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:
    # 주봉 가격 확인
    result = conn.execute(text('''
        SELECT symbol, COUNT(*) as cnt, MIN(week_start) as oldest, MAX(week_start) as newest
        FROM kr_index_prices_weekly GROUP BY symbol
    '''))
    print('=== 주봉 가격 데이터 ===')
    for row in result:
        print(f'  {row[0]}: {row[1]}건 ({row[2]} ~ {row[3]})')

    # 주봉 지표 확인
    result = conn.execute(text('''
        SELECT symbol, indicator, COUNT(*) as cnt
        FROM kr_index_indicators_weekly GROUP BY symbol, indicator
    '''))
    print('\n=== 주봉 지표 데이터 ===')
    for row in result:
        print(f'  {row[0]} | {row[1]}: {row[2]}건')
"
```

#### 데이터 저장 방식

- **가격**: `INSERT IGNORE` (기존 데이터 보존, 중복 무시)
- **지표**: `INSERT ONLY` (기존 데이터 보존, 중복 무시)
- **NaN 처리**: warmup 기간 등으로 지표값이 계산 불가능한 경우 `NULL`로 저장 (`keep_nan=True`)
- 재실행해도 기존 데이터를 덮어쓰지 않으므로 안전합니다 (멱등성 보장)

### Step 3: 주봉 증분 업데이트

**목적**: 매주 장마감 후 최신 주봉 데이터 및 지표를 증분 업데이트

```bash
# 3-1. 전체 지수 업데이트 (추천)
python apps/ingest-databatcher/scripts/kr_index_weekly_update.py --all

# 3-2. KOSPI 지수만 업데이트
python apps/ingest-databatcher/scripts/kr_index_weekly_update.py --all --market KOSPI

# 3-3. 특정 지수만 업데이트
python apps/ingest-databatcher/scripts/kr_index_weekly_update.py --symbols 1001
```

#### CLI 옵션

| 옵션 | 필수 | 설명 | 기본값 |
|------|------|------|--------|
| `--all` | 택1 | 모든 ACTIVE 지수 업데이트 | - |
| `--symbols` | 택1 | 특정 지수코드 리스트 (예: 1001 2001) | - |
| `--market` | X | KOSPI / KOSDAQ / ALL (`--all`과 함께 사용) | ALL |

> `--all` 또는 `--symbols` 중 하나는 반드시 지정해야 합니다.

#### 동작 방식

1. **일봉 조회**: DB에서 최근 250주(~1750일) `kr_index_prices` 일봉 데이터 조회
2. **주봉 집계**: `aggregate_daily_to_weekly_trading_days()` 로 주봉 생성
    - 평일(월~금): 최신 주차 스킵 (`skip_latest_week=True`, 미완성 주차 방지)
    - 주말(토/일): 최신 주차 포함 (`skip_latest_week=False`, 직전 금요일 종가까지 확정)
    - 주말 최신 주 포함 시, 최신 주 `week_end`가 실행 기준일(`end_date`)과 다르면 최신 주를 스킵
3. **가격 저장**: 주봉 가격 `INSERT IGNORE` → `kr_index_prices_weekly`
4. **지표 계산**: warmup 포함 일봉 추가 조회 → 주봉 집계 → 지표 계산
5. **역순 저장**: 최신 주부터 역순으로 처리
   - `IndicatorChecker`로 모든 지표가 이미 완료된 주를 만나면 **조기 중단**
   - 미완성 주만 `INSERT ONLY`로 저장

#### 예상 출력 (첫 실행)

```
[kr_index_weekly_update] skip_latest_week=False (KST weekend -> False)
[kr_index_weekly_update] 기준일: 2026-02-06
[kr_index_weekly_update] 처리 대상: 2개 지수
1001: 주봉 가격 8건 처리(insert-only)
1001: 2026-01-26 모든 지표 완료 → 중단
1001: 1개 주 처리, 지표 4건 저장(insert-only)
2001: 주봉 가격 8건 처리(insert-only)
2001: 2026-01-26 모든 지표 완료 → 중단
2001: 1개 주 처리, 지표 4건 저장(insert-only)
[kr_index_weekly_update] 완료
```

#### 예상 출력 (재실행 - 이미 최신)

```

2001: 0개 주 처리, 지표 0건 저장(insert-only)

```

#### 데이터 저장 방식

- **가격**: `INSERT IGNORE` (기존 데이터 보존)
- **지표**: `INSERT ONLY` (기존 데이터 보존)
- **NaN 처리**: warmup 기간 지표값은 `NULL`로 저장
- **IndicatorChecker**: 있음 (최신 주부터 역순으로 확인, 완료된 주 감지 시 조기 중단)
- **로그 해석 주의**: 가격 로그의 건수는 처리/삽입 시도 건수이며, 실제 신규 삽입 건수와 다를 수 있습니다.

## 4. 정규 운영 방법

### 4.1. 주간 작업: 주봉 업데이트

**실행 주기**: 매주 토요일 (금요일 장마감 후 일봉 데이터 확정 이후)

```bash
python apps/ingest-databatcher/scripts/kr_index_weekly_update.py --all
```

> 토요일/일요일에 실행하면 `skip_latest_week=False`로 동작하여 직전 금요일까지의 주봉이 포함됩니다.

### 4.2. 재생성 (Backfill)

과거 누락 구간의 주봉을 채우려면 `kr_index_bulk_update_weekly.py`를 사용합니다.

```bash
# 특정 기간 주봉 재생성
python apps/ingest-databatcher/scripts/kr_index_bulk_update_weekly.py --start 2023-01-01 --end 2023-12-31

# DB 전체 기간 재생성
python apps/ingest-databatcher/scripts/kr_index_bulk_update_weekly.py
```

`INSERT IGNORE`로 동작하므로 기존 데이터는 보존되고 없는 주만 추가됩니다.

## 6. DB 스키마

### 테이블 구조

#### kr_index_prices_weekly (지수 주봉 가격)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| symbol (PK) | VARCHAR(32) | 지수 코드 (1001, 2001) |
| week_start (PK) | DATE | 주의 첫 거래일 |
| week_end | DATE | 주의 마지막 거래일 |
| open | DECIMAL(18,4) | 시가 (첫 거래일) |
| high | DECIMAL(18,4) | 고가 (주간 최고) |
| low | DECIMAL(18,4) | 저가 (주간 최저) |
| close | DECIMAL(18,4) | 종가 (마지막 거래일) |
| volume | BIGINT | 거래량 (주간 합계) |
| market | VARCHAR(16) | KOSPI / KOSDAQ |
| source | VARCHAR(16) | pykrx |
| etl_loaded_at | TIMESTAMP | 적재 시각 |

> **참고**: 일봉(`kr_index_prices`)과 마찬가지로 `adj_close` 컬럼이 없습니다. 지수는 수정주가 개념이 불필요합니다.

#### kr_index_indicators_weekly (지수 주봉 기술적 지표)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| symbol (PK) | VARCHAR(32) | 지수 코드 |
| week_start (PK) | DATE | 주의 첫 거래일 |
| indicator (PK) | VARCHAR(64) | 지표명 (sma_5_close 등) |
| params_hash (PK) | CHAR(40) | 파라미터 해시 (SHA1) |
| value | DECIMAL(28,10) | 지표값 (NULL 가능) |
| market | VARCHAR(16) | KOSPI / KOSDAQ |
| source | VARCHAR(16) | pykrx |
| etl_loaded_at | TIMESTAMP | 적재 시각 |

### VIEW

#### v_kr_index_price_weekly_with_ma

주봉 가격과 주요 이동평균선을 결합한 뷰입니다.

| 컬럼 | 설명 |
|------|------|
| symbol | 지수 코드 |
| week_start | 주 시작일 |
| week_end | 주 종료일 |
| open, high, low, close, volume | OHLCV |
| sma_5 | SMA(5, close) |
| sma_20 | SMA(20, close) |
| ema_12 | EMA(12, close) |
| ema_26 | EMA(26, close) |

```sql
-- 사용 예시
SELECT * FROM v_kr_index_price_weekly_with_ma
WHERE symbol = '1001'
ORDER BY week_start DESC
LIMIT 10;
```

### 테이블 간 관계

```
kr_index_master (2건)
  ├── kr_index_prices (일봉) ──[집계]──> kr_index_prices_weekly (주봉)
  ├── kr_index_indicators (일봉 지표)
  └── kr_index_indicators_weekly (주봉 지표)
```

```yaml
      save: true
```

**기본 지표 목록** (일봉과 동일):

| 지표 | 파라미터 | DB indicator 컬럼값 |
|------|----------|---------------------|
| SMA | window=5, column=close | sma_5_close |
| SMA | window=20, column=close | sma_20_close |
| EMA | window=12, column=close | ema_12_close |
| EMA | window=26, column=close | ema_26_close |

> 지표를 추가/변경하려면 `apps/ingest-databatcher/config/settings.yaml`의 `indicators_kr_index_weekly.pipeline` 섹션을 수정하세요.

## 9. FAQ 및 트러블슈팅

### Q1. `kr_index_prices 테이블이 비어있습니다`

**원인**: 일봉 데이터가 아직 적재되지 않음

**해결**:
```bash
# 일봉 마스터 동기화 + 데이터 수집 먼저 실행
python apps/ingest-databatcher/scripts/kr_index_sync_master.py
python apps/ingest-databatcher/scripts/kr_index_bulk_update.py --start 2024-01-01 --end 2024-12-31
```

---

### Q2. 주봉 지표가 일부 NULL로 저장됨

**정상 동작입니다.** warmup 기간(예: SMA(20)은 최소 20주 필요)에 해당하는 주의 지표값은 계산이 불가능하므로 `NULL`로 저장됩니다.

**확인**:
```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBManager, DBConfig
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:
    result = conn.execute(text('''
        SELECT indicator,
               COUNT(*) as total,
               SUM(CASE WHEN value IS NULL THEN 1 ELSE 0 END) as null_cnt
        FROM kr_index_indicators_weekly
        GROUP BY indicator
    '''))
    for row in result:
        print(f'{row[0]}: 전체 {row[1]}건, NULL {row[2]}건')
"
```

---

### Q3. bulk 후 weekly_update 실행 시 "모든 지표 완료 -> 중단"

**정상 동작입니다.** `bulk_update_weekly`로 이미 적재된 기간의 지표가 모두 존재하면, `weekly_update`는 해당 주에서 조기 중단합니다. 새로운 주가 추가되었을 때만 신규 데이터가 저장됩니다.

---

### Q4. 평일에 실행하면 최신 주가 빠짐

**정상 동작입니다.** 평일에는 현재 주가 아직 완성되지 않았으므로 `skip_latest_week=True`로 동작합니다. 토요일/일요일에 실행하면 직전 금요일까지의 데이터가 확정된 것으로 간주하여 최신 주를 포함합니다.

> 주차 포함/스킵 판단은 실행 요일 기반 `skip_latest_week` 로직으로 결정됩니다.

---

### Q5. 주말 실행인데 최신 주가 스킵됨

최신 주 `week_end`가 실행 기준일(`end_date`)과 다르면 최신 주를 미완결로 판단해 스킵합니다.

**확인 포인트**:
- 금요일(또는 해당 주 마지막 거래일) 일봉이 `kr_index_prices`에 적재됐는지 확인
- 주말 실행 전에 일봉 파이프라인(`kr_index_daily_update.py`)이 정상 완료됐는지 확인

---

### Q6. 일봉 파이프라인에 영향이 있나요?

**없습니다.** 주봉 파이프라인은 완전히 별도의 테이블(`kr_index_prices_weekly`, `kr_index_indicators_weekly`)을 사용하므로, 기존 일봉 테이블(`kr_index_prices`, `kr_index_indicators`)에는 영향이 없습니다.
