### 타당성 검토 요약
- 지적하신 4가지 핵심 포인트(수정주가 이벤트 처리, EMA/RSI 경계 왜곡, 티커 자동화, MySQL/레이트리밋 안정성) 모두 현실적인 리스크이며, 실무 운영에서 반드시 대비가 필요한 항목입니다. 특히 수정주가 이벤트 시 과거 데이터 재동기화(Re-sync), 지표의 충분한 워밍업 및 주기적 정합성 검증, 종목 마스터 자동 동기화, 배치/레이트리밋 튜닝은 필수입니다.
- 추가 제안하신 관측 가능성(health check, gap 리포팅)도 매우 타당하며, 운영 신뢰도를 크게 높입니다.

아래는 v1+v2를 통합하고 위 리스크 완화 방안을 반영한 “최종 프로젝트 계획안”입니다.

---

### 1) 목표와 원칙
- 목표: FDR 기반 멀티마켓(한국/미국/크립토) 가격 수집과 모듈형 지표 생성·저장을 안정적으로 운영. 데이터 정합성·확장성·관측 가능성 확보.
- 원칙:
  - 멱등성: `(symbol, date)`(가격), `(symbol, date, indicator, params_hash)`(지표) 유니크 키 기반 업서트.
  - 플러그인 지표: `BaseIndicator`/레지스트리/파이프라인으로 레고식 조합.
  - 설정 주도: 지표/저장전략/스케줄/레이트리밋/워밍업 등은 `settings.yaml`로 외부화.
  - 관측 가능성: 구조화 로그 + 메트릭 + 건강상태 테이블.

---

### 2) 아키텍처 개요 및 폴더
- 수집: `collectors/*` (FDR 등)
- 지표: `indicators/*` + `IndicatorPipeline`
- 저장: `savers/*` (가격/지표 long·wide·hybrid)
- 실행: `scripts/*` (init/daily/gap/resync/ticker_sync)
- 공통: `core/*` (DB, 캘린더, 로깅, 파라미터 해시, 레이트리밋/리트라이)
- 마이그레이션: `migrations/`

프로젝트 구조는 v2 제안과 동일(추가 스크립트/테이블 아래 명시).

### 3) 데이터 모델(DDL 핵심)
- 가격 테이블: v1에 제시한 `stock_prices`, `crypto_prices` 유지. `close`(원시/수정전)와 `adj_close`(수정후)를 함께 저장. 시장/소스/적재시각 포함. PK `(symbol, date)`.
- 지표 테이블(Long form): v2의 `stock_indicators` 유지. PK `(symbol, date, indicator, params_hash)`.
- 종목 마스터: 신규 `symbol_master` 도입.
```
CREATE TABLE IF NOT EXISTS symbol_master (
  symbol        VARCHAR(32) PRIMARY KEY,
  market        VARCHAR(16) NOT NULL,      -- XKRX/XNYS/CRYPTO 등
  name          VARCHAR(128) NULL,
  status        VARCHAR(16) NOT NULL,      -- ACTIVE/DELISTED/IPO_PENDING
  first_date    DATE NULL,
  last_date     DATE NULL,
  updated_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
- 동기화 로그/헬스체크: `sync_log` 도입.
```
CREATE TABLE IF NOT EXISTS sync_log (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  job_name      VARCHAR(64) NOT NULL,      -- daily_update, gap_filler, resync 등
  market        VARCHAR(16) NOT NULL,
  symbol        VARCHAR(32) NULL,
  start_time    DATETIME NOT NULL,
  end_time      DATETIME NULL,
  rows_processed INT DEFAULT 0,
  status        VARCHAR(16) NOT NULL,      -- SUCCESS/FAIL/PARTIAL
  message       VARCHAR(1024) NULL,
  created_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_job_market_time (job_name, market, start_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4) 시간/캘린더/시간대 전략
- `core/date_utils.py`는 v1 구현을 사용. NYSE DST는 `pandas_market_calendars`가 처리. 시장별 마감버퍼는 설정값(`safe_delay_minutes`)으로 제어.
- 암호화폐는 365일 운영: 일자 경계 기준을 `UTC`로 고정 권장(설정으로 선택 가능). 저장 시 `date`는 해당 기준으로 일자화.

---

### 5) 지표(Indicator) 모듈 전략
- v2의 `BaseIndicator`/`IndicatorRegistry`/`IndicatorPipeline` 채택.
- 워밍업 원칙: 각 지표 `warmup()`은 보수적으로 설정. EMA/RSI는 `window * 5` 권장(설정에서 상향 조정 가능).
- 저장 전략: `long|wide|none|hybrid` 설정. 파라미터 해시로 공존·멱등성 확보.
- 검증: 각 지표는 `required_columns()`로 입력 컬럼 체크, NaN 비율 과다 시 저장 제외 옵션.

### 6) ETL 워크플로우
1) 초기 적재 `scripts/init_load.py`
- 각 시장/심볼 마스터 기반 전체 기간 수집.
- 가격 저장 → 지표 파이프라인 실행 → 선택 전략에 따라 지표 저장.
- 대용량 시 종목 단위 병렬 + 배치 업서트(chunksize) 적용.

2) 일일 갱신 `scripts/daily_update.py`
- 시장별 마감+버퍼 확인 후 당일분 수집.
- 최신일자 기준 `warmup_days()`만큼 되돌아가 지표 재계산(경계 보정).
- 배치 업서트, 레이트 리밋, 리트라이 적용.

3) 갭 보충 `scripts/gap_filler.py`
- `(symbol, MAX(date))` < `last_business_day`이면 중간 구간만 수집 및 업서트.
- 연속 누락이 길거나 FDR 응답 없음 → 경고/보류 큐 로깅.

4) 재동기화(Resync) `scripts/resync_corporate_actions.py`
- 트리거: 분할/병합/배당 등 이벤트 감지 시 수행.
- 전략:
  - 과거 전체 구간 재수집(원시 `close`와 `adj_close` 동시 저장).
  - 해당 기간 지표를 전량 재계산 및 재저장.
- 이벤트 감지 휴리스틱(소스 한정 시):
  - 하루 사이 `adj_close/close` 비율 급변(예: 0.4~0.6, 1.9~2.1 등) 또는 특정 패턴 지속.
  - `fdr.StockListing('KRX')` 등 메타데이터 변화(주식 액면분할 공시 반영 추정).
  - 월 1회 전체 스냅샷과 비교해 레벨 쉬프트 감지.

예시 의사코드:
```python
# scripts/resync_corporate_actions.py
for symbol in symbols:
    ratios = detect_split_ratio_candidates(engine, symbol)  # adj_close/close 급변 탐지
    if ratios:
        full = collector.fetch(symbol, start='2010-01-01', end=last_biz)
        full = collector.validate(full)
        DBManager.upsert_dataframe(engine, full, table=collector.table)
        # 지표 전량 재계산
        dfp = full.assign(date=pd.to_datetime(full['date'])).set_index('date')
        outputs = pipe.run(dfp)
        if saver.mode in ("long","hybrid"):
            df_long = pipe.to_long_dataframe(symbol, market, 'FDR', dfp.index, outputs)
            saver.save_long(df_long)
        if saver.mode in ("wide","hybrid"):
            merged = saver.merge_wide(dfp, outputs).reset_index()
            merged['symbol']=symbol; merged['market']=market; merged['source']='FDR'
            DBManager.upsert_dataframe(engine, merged, table=collector.table)
```

### 7) 티커 관리 자동화
- 신규 스크립트 `scripts/ticker_sync.py` 도입.
  - `fdr.StockListing('KRX')`, `fdr.StockListing('NASDAQ')` 등 사용(가용 시)하여 최신 리스트 수집.
  - `symbol_master`에 업서트: 신규 심볼 추가, 상폐/변경 상태 업데이트.
  - `init_load` 이전·`daily_update` 직전에 실행하여 대상 심볼 집합을 항상 최신화.
- 분석용 그룹(예: KOSPI200, S&P500)도 동기화 스크립트 제공.

### 8) 성능/안정성 설계
- 배치 업서트(가격/지표): `chunksize` 파라미터 도입(예: 1000~5000). 인덱스 영향 최소화.
- 레이트 리밋 + 지터:
```python
def next_sleep(interval):
    # interval = 1.0 / rate_per_sec
    import random
    return max(0.0, interval * random.uniform(0.8, 1.4))
```
- 스레드풀: API 제한과 DB 부하를 감안한 워커(예: 5~10). I/O 중심 수집과 CPU 중심 지표 계산을 분리(옵션으로 프로세스풀).
- 연결풀: SQLAlchemy 엔진 설정(v1) 유지. `pool_pre_ping=True`.
- 재시도/백오프: 지수 백오프 + 지터. `HTTP 429/5xx` 전용 재시도 규칙.

### 9) 데이터 품질/정합성
- 가격 검증: `Open/High/Low/Close>0`, `Low<=High`, `Volume>=0`. 이상치(상위 99.9 분위) 경고.
- 지표 검증: NaN 비율 상한(예: 10%) 초과 시 저장 제외.
- 스냅샷 대조: 월 1회 전체 재계산 스냅샷과 증분 결과 비교(EMA/RSI 경계 오차 점검). 차이가 임계치 초과 시 자동 Resync 큐 등록.

### 14) 단계별 마일스톤
- M1: DB 스키마/엔진/기본 수집(KRX) + daily_update POC
- M2: IndicatorPipeline 통합 + long 저장 + 워밍업 증분
- M3: ticker_sync + gap_filler + 관측 가능성(로그/헬스테이블)
- M4: resync_corporate_actions(감지+전량재계산) + 월간 스냅샷 검증
- M5: 성능 최적화(chunksize, rate jitter, 멀티스레드 튜닝) + US/CRYPTO 확장
- M6: Airflow/Prefect DAG화 및 운영 가이드 정리

### 15) 구현 상세 보완(샘플 코드/패턴)
- 배치 업서트 인터페이스 확장:
```python
# savers/upsert.py
from typing import Iterable

def upsert_in_batches(engine, df, table: str, unique_keys: tuple, chunksize: int = 2000):
    if df is None or df.empty:
        return 0
    total = 0
    for i in range(0, len(df), chunksize):
        batch = df.iloc[i:i+chunksize]
        total += DBManager.upsert_dataframe(engine, batch, table=table, unique_keys=unique_keys)
    return total
```
- 레이트 리밋 + 지터 적용 맵:
```python
def rate_limited_submit(executor, func, items, rate_per_sec=5):
    import time, random
    interval = 1.0 / max(1, rate_per_sec)
    last = 0.0
    futures = []
    for item in items:
        now = time.time()
        sleep = max(0.0, interval - (now - last)) * random.uniform(0.8, 1.4)
        if sleep: time.sleep(sleep)
        last = time.time()
        futures.append(executor.submit(func, item))
    return futures
```

### 결론
- v1+v2 설계는 이미 견고하며, 본 계획안은 실제 운영에서의 리스크(수정주가 이벤트, 지표 경계, 티커 자동화, 부하/레이트리밋, 관측 가능성)를 체계적으로 보완합니다.
- 이 상태로 즉시 개발에 착수 가능하며, 우선순위는 다음과 같습니다: 1) `symbol_master`/`ticker_sync` 구현 → 2) 워밍업 증분 + 배치 업서트/레이트 지터 → 3) `resync_corporate_actions` 파이프라인 + 월간 스냅샷 검증.

원하시면 `ticker_sync.py`와 `resync_corporate_actions.py`의 구체 코드 템플릿, 그리고 Airflow DAG 예시까지 추가로 제공해 드리겠습니다.
