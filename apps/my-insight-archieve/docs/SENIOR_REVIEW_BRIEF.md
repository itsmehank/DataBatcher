# My Insight Archive - 시니어 리뷰 요청 문서

## 1) 프로젝트 목적

이 프로젝트는 개인이 AI와 나눈 대화 중 다시 볼 가치가 있는 내용을 구조적으로 아카이빙하기 위한 웹 서비스입니다.

- 카테고리별로 대화 내용을 정리
- 대화 링크(URL)와 출처(ChatGPT/Claude/Gemini/기타) 저장
- 개인 메모 및 태그 기반 회고/검색
- 자주 재사용하는 템플릿(프롬프트) 별도 보관
- MongoDB 전체 데이터 백업(최신 1개 유지) 지원

핵심 사용 시나리오:

1. 대화에서 인사이트 발견
2. 아카이브에 카테고리/메모/링크와 함께 저장
3. 유용한 프롬프트는 템플릿으로 축적
4. 주기적으로 관리자 페이지에서 DB 백업 수행

---

## 2) 현재 구현 상태 (기술)

### 아키텍처

- Frontend: Next.js (App Router, TypeScript)
- Backend: NestJS + Mongoose
- Database: MongoDB (Docker 컨테이너)
- Orchestration: Docker Compose

### 백엔드 구현 범위

- 인증
  - 관리자 로그인 (`POST /api/auth/login`)
  - JWT 기반 보호 라우트
- 카테고리
  - 기본 카테고리 seed + 사용자 커스텀 카테고리
  - 카테고리 삭제 시 엔트리 `미분류` 이동
- 아카이브 엔트리
  - CRUD API
  - 카테고리/키워드/출처 필터 조회
- 템플릿
  - CRUD API
  - 태그/키워드 조회
- 백업
  - 관리자 전용 `POST /api/admin/backup/export`
  - `GET /api/admin/backup/status`
  - 서버 파일 `backups/latest.archive.gz` 단일 유지 정책

### 백업 정책 요약

- 전체 컬렉션 데이터 export
- 기존 export는 제거하고 최신 파일 1개만 유지
- 동시 실행 방지 플래그 적용
- 실패 시 상태 메시지 기록

## 3) 현재 프론트 페이지 모습 및 UX

현재 UI는 "차분한 노션형" 톤으로 통일 중이며, 작성보다 목록 탐색 중심 UX로 구성했습니다.

### 공통 톤/레이아웃

- 밝은 중성 배경 + 소프트 카드(라운드/얕은 섀도우)
- 상단 고정 네비: 아카이브 / 템플릿 / 어드민 / 관리자 로그인
- 카드형 메시지 보관 UI(태그 칩, 메타 정보, 액션 구역)

### A. 아카이브 페이지 (`/`)

- 메인에 저장된 아카이브 카드 목록 노출
- 우하단 `+` FAB 클릭 시 작성 드로어 오픈
- 드로어에서 제목/내용/메모/대화링크/출처/카테고리/태그 입력
- 닫기 동작
  - `ESC` 또는 배경 클릭: 닫기
  - `X`: 닫기(작성 내용 유지)
  - `취소`: 폼 초기화 후 닫기
- 카드 표시 요소
  - 카테고리, 날짜, 출처, 본문 미리보기, 메모, 태그, 링크

### B. 템플릿 페이지 (`/templates`)

- 아카이브와 동일 UX 패턴(FAB + 우측 드로어)
- 드로어 입력 항목
  - 템플릿 이름, 본문, 설명, 사용 상황(use case), 태그
- 카드 표시 요소
  - 템플릿명, 설명, 본문 미리보기, 태그, 복사 버튼
- 저장 후 목록 갱신 및 성공 메시지 표시

### C. 어드민 페이지 (`/admin`)

- 백업 전용 화면으로 분리
- 관리자 인증 상태에서만 백업 실행/상태 조회
- 비인증 시 로그인 유도 메시지 표시

### D. 로그인 페이지 (`/login`)

- 관리자 로그인/로그아웃
- JWT를 프론트 저장소(localStorage)에 저장하여 보호 API 호출

## 4) 시니어 리뷰에서 받고 싶은 피드백

아래 항목 중심으로 개선 의견을 받고 싶습니다.

1. **아키텍처/보안**
   - JWT 저장 방식(localStorage) 적절성
   - 관리자 기능 보호 전략(세션/쿠키 전환 여부)
   - 백업 API 보안 및 운영성

2. **도메인 모델링**
   - Entry/Template/Category 스키마 확장성
   - 인덱스 전략(검색/정렬/대량 데이터 대비)

3. **백업/복구 운영성**
   - 현재 export 방식(JSON+gzip)과 `mongodump` 기반 방식의 트레이드오프
   - restore 자동화 전략
   - 백업 실패/파일 손상 시 검증 절차

4. **프론트 구조화**
   - 현재 페이지 단위 구현을 컴포넌트 단위로 분리할 기준
   - 공통 카드/드로어/폼 상태 훅 추출 방향
   - 폼 유효성/에러 UX 개선 제안

5. **제품 UX**
   - 카드 정보 밀도와 가독성 균형
   - 검색/정렬/필터 UX 우선순위
   - 템플릿 재사용 흐름(복제, 즐겨찾기, 버전관리) 제안
