좋아. 그러면 바로 작업에 들어갈 수 있게 **“무엇부터, 어떤 순서로, 어떤 기준으로”** 바꿔야 하는지 기준서처럼 정리해볼게.

핵심은 하나야.

**지금의 화면은 ‘기능을 담은 페이지’이고, 앞으로는 ‘제품 인상을 만드는 화면’으로 바꿔야 한다.**

즉, 카드 예쁘게 꾸미는 수준이 아니라 아래 4가지를 먼저 재설계해야 해.

* 브랜드 톤
* 레이아웃 계층
* 컴포넌트 규칙
* 화면별 역할

---

# 1. 먼저 정해야 할 디자인 방향

네 프로젝트는 그냥 메모앱이 아니라
**“AI 대화에서 건진 인사이트를 아카이빙하고 다시 꺼내 쓰는 제품”**처럼 보여야 해.

그래서 디자인 방향은 아래처럼 잡는 걸 추천해.

## 추천 방향

**Apple의 절제된 프리미엄 감성 + Linear의 현대적인 제품 밀도 + Notion의 정보 구조**

이걸 실제 UI 언어로 바꾸면:

* 화면은 밝고 정제되어야 함
* 타이포는 크고 시원해야 함
* 정보는 많아도 어수선하면 안 됨
* 카드가 단순 CRUD 박스처럼 보이면 안 됨
* 인터랙션은 적지만 정교해야 함
* “AI가 생성한 기본 템플릿” 느낌을 없애야 함

---

# 2. 가장 먼저 해야 할 일: 디자인 원칙 6개 고정

코드 수정 전에 먼저 아래 원칙을 정해.
이게 없으면 작업하다가 다시 올드한 화면으로 돌아가.

## 원칙 1. 컬러는 적게

포인트 컬러를 여러 개 쓰지 말고, 거의 무채색 중심으로 가.

예시:

* 배경: 매우 옅은 쿨그레이
* 카드: 흰색
* 본문 텍스트: 거의 검정
* 보조 텍스트: 중간 회색
* 포인트 컬러: 1개만

## 원칙 2. 선보다 면과 간격으로 구분

박스마다 border를 두르는 방식은 금방 올드해 보여.

* 구분은 여백
* 레이어 차이는 shadow
* 강조는 크기/무게/간격

위주로 처리해.

## 원칙 3. 타이포 위계를 강하게

지금 같은 “제목도 본문도 다 비슷비슷한 크기”가 가장 흔한 AI 사이트 느낌을 만든다.

페이지마다:

* 가장 큰 문장 1개
* 그 다음 핵심 설명 1개
* 나머지 정보는 작게

이 계층이 명확해야 해.

## 원칙 4. 모든 요소는 이유가 있어야 함

태그, 아이콘, 버튼, 배지, 구분선이 많아질수록 조잡해져.

추가 기준:

* 이 요소가 탐색을 빠르게 하나?
* 이 요소가 브랜드 인상을 강화하나?
* 둘 다 아니면 제거

## 원칙 5. 화면마다 ‘한 장면의 인상’이 있어야 함

첫 화면은 첫 화면답게,
아카이브는 아카이브답게,
템플릿은 템플릿답게 보여야 해.

지금처럼 모든 페이지가 비슷한 카드 나열이면 안 돼.

## 원칙 6. 모션은 적고 부드럽게

애플 느낌은 화려한 애니메이션이 아니라
**절제된 반응성**에서 나와.

* hover: 살짝 뜸
* 필터 전환: 부드럽게
* 페이지 진입: 페이드 + 위로 8~12px 정도

과한 확대/회전/튕김은 피하는 게 좋아.

# 3. 작업 순서

이 순서대로 하면 시행착오가 훨씬 줄어.

## 1단계: 디자인 토큰부터 정리

먼저 스타일 기준을 고정해.

정해야 할 것:

* 색상
* 폰트 크기 체계
* 폰트 두께 체계
* radius
* shadow
* spacing scale
* max width

이걸 먼저 정하지 않으면 컴포넌트마다 제각각이 된다.

### 추천 토큰 예시

#### Color

* `bg-primary`: `#f5f5f7`
* `bg-secondary`: `#ffffff`
* `text-primary`: `#111111`
* `text-secondary`: `#6e6e73`
* `border-soft`: `rgba(0,0,0,0.08)`
* `accent`: `#2563eb` 또는 아주 차분한 청록/블루

#### Radius

* page card: 24px
* small card: 20px
* input/button: 14~16px
* pill: 9999px

#### Shadow

* 기본: 매우 약한 shadow
* hover: 살짝 더 진한 soft shadow
* inset shadow는 거의 쓰지 않기

#### Spacing

* 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72 / 96
  이 정도 스케일로 통일

#### Typography

* hero: 48~64
* section title: 28~36
* card title: 20~24
* body: 16~18
* meta: 12~13

---

## 2단계: 레이아웃 시스템 재설계

전체 페이지 뼈대를 먼저 바꿔.

### 추천 레이아웃

* 전체 max width: 1200~1320px
* 좌우 padding: 24~40px
* 상단 nav 높이: 64~72px
* 섹션 간격: 64~120px
* 카드 간격: 20~24px

### 중요한 포인트

지금은 페이지가 너무 넓게 비고, 콘텐츠 덩어리는 왼쪽에 작게 몰려 보여.
그래서 화면이 고급스러워 보이기보다 허전해 보여.

해결하려면:

* hero 구역은 넓게 쓰고
* 본문은 구조화하고
* 카드 영역은 의도적으로 grid를 잡아야 해

# 4. 페이지 구조 가이드

이제 각 페이지를 어떻게 구성하면 되는지 말해볼게.

---

## A. 아카이브 메인 페이지

이 페이지가 가장 중요해.
지금처럼 그냥 카드 하나 놓는 방식은 안 돼.

### 추천 구조

### 1) Hero 영역

맨 위 첫 화면은 제품 정체성을 설명하는 구역이어야 해.

구성:

* 큰 헤드라인
* 한 줄 설명
* CTA 버튼 2개
* 우측 또는 하단에 실제 아카이브 UI preview

예시:

* 헤드라인: “흘려보내기 아까운 생각을 저장하세요”
* 설명: “AI와의 대화에서 건진 아이디어를 구조화해 다시 꺼내보는 개인 인사이트 아카이브”
* 버튼: “아카이브 보기”, “새 항목 작성”

### 2) 탐색 바

Hero 아래 바로 탐색 도구가 와야 해.

구성:

* 검색창
* 카테고리 필터
* 출처 필터
* 정렬
* 보기 전환(grid/list)

이 부분은 sticky로 가도 좋음.

### 3) Featured Insight

최신순 카드만 놓지 말고, 대표 항목 하나를 크게 보여줘.

구성:

* 큰 카드 1개
* 제목
* 요약
* 태그
* 출처
* 메모 일부
* 대화 열기 CTA

이 카드가 제품의 품질을 끌어올려 보여주는 역할을 한다.

### 4) Recent Archive Grid

그 아래 일반 카드 그리드.

추천:

* 데스크탑 3열
* 태블릿 2열
* 모바일 1열

### 5) Empty / Secondary area

비어 있는 공간을 그냥 두지 말고 의미를 넣어.

예:

* 자주 쓰는 태그
* 최근 출처
* 이번 주 저장 수
* 추천 템플릿
* 최근 다시 본 항목

---

## B. 카드 컴포넌트 구조

이건 정말 중요해.
카드가 예쁘지 않으면 아무리 배경을 바꿔도 소용없어.

### 카드 구조 추천

1. 상단 메타

   * 카테고리
   * 날짜
   * 출처

2. 메인 타이틀

   * 가장 강조
   * 1~2줄

3. 요약 본문

   * 2~3줄
   * 너무 길지 않게

4. 보조 정보

   * 메모
   * 태그 2개 정도
   * 관련 링크 수

5. 액션

   * 열기
   * 원문 대화 보기
   * 저장/편집

### 카드 디자인 기준

* 배경은 순백색
* border는 거의 안 보이게
* shadow는 약하게
* hover 시 약간 위로 떠오름
* 텍스트 간 간격 넉넉하게
* 버튼은 많지 않게

### 카드에서 줄여야 할 것

* 설명 문장 과다 노출
* 태그 너무 많이 보여주기
* 아이콘 남발
* 링크를 여러 줄로 늘어놓기
* 메타 정보 과다 노출

---

## C. 템플릿 페이지

템플릿 페이지는 아카이브랑 동일한 패턴으로 만들면 안 돼.
역할이 다르기 때문이야.

### 템플릿 페이지 역할

* 바로 복사해서 쓰는 도구
* 빠르게 선택하는 라이브러리
* 생산성 중심

### 추천 구조

1. 페이지 헤더

   * 제목
   * 설명
   * 검색
   * 필터

2. 자주 쓰는 템플릿

   * 상단 강조

3. 카테고리별 템플릿

   * 글쓰기
   * 정리
   * 회고
   * 기획
   * 브레인스토밍

4. 템플릿 카드

   * 제목
   * 설명
   * 사용 상황
   * 복사 버튼

### 디자인 포인트

* 아카이브보다 더 기능 중심
* 카드 높이 균일
* preview가 지나치게 길면 안 됨
* 복사 버튼은 확실히 보여야 함

---

## D. 로그인 / 관리자 페이지

여긴 감성보다 신뢰감이 중요해.

### 방향

* 미니멀
* 절제
* 기능 중심
* 관리툴의 명확성

### 추천

* 좌우 분할보다는 단순 중앙 정렬
* 카드 하나 안에 로그인 폼
* 관리자 화면은 테이블/리스트 기반
* 장식은 최소화

# 5. 네비게이션 구조 가이드

지금 네비는 그냥 텍스트 링크처럼 보여서 약해.

### 추천 구조

좌측:

* 로고 또는 워드마크

중앙 또는 우측:

* 아카이브
* 템플릿
* 소개 또는 어드민 진입

우측 끝:

* 로그인 / 프로필

### 스타일

* 반투명 상단 바 가능
* 스크롤 시 약한 blur
* 현재 페이지 강조는 과하지 않게
* 메뉴 간격 넓게
* 클릭 영역 충분히 크게

### 피해야 할 것

* 메뉴 항목이 너무 많아지는 것
* 네비 바에 박스나 선을 너무 많이 넣는 것
* 관리자 메뉴를 일반 사용자 메뉴처럼 같은 급으로 보이게 하는 것

# 6. 타이포 가이드

AI가 만든 느낌을 없애는 데 가장 강력한 수단이 타이포야.

## 규칙

* 헤드라인은 크고 짧게
* 설명 문장은 얇고 절제되게
* 카드 제목은 명확하게
* 메타 정보는 작고 조용하게
* 한 화면 안에서 글자 크기 종류를 너무 많이 쓰지 않기

## 추천 체계

* Display: 56
* H1: 40
* H2: 32
* H3: 24
* Body: 16
* Small: 13

## 문장 스타일

* 문장을 길게 늘이지 말기
* 설명은 짧게 끊기
* UI 카피는 “기능 설명”보다 “행동 유도” 위주로

예:

* “대화 링크 열기” 좋음
* “저장된 대화 링크를 확인할 수 있습니다” 별로

---

# 7. 컬러와 질감 가이드

애플 느낌을 내고 싶으면, 색을 화려하게 쓰는 게 아니라
**빛의 밀도 차이**를 잘 써야 해.

## 추천 방식

* 전체 배경은 연한 쿨그레이
* 카드/입력창은 흰색
* 강조는 텍스트 대비로
* 포인트 컬러는 아주 제한적으로만

## 질감

* 미세한 그라디언트는 가능
* 큰 덩어리 배경 블러는 과하면 AI 랜딩페이지처럼 보임
* 유리효과는 아주 절제해서만
* 반짝이는 효과, 형광 느낌, 네온 느낌은 피하기

---

# 8. 인터랙션 가이드

좋은 사이트는 멈춰 있어도 예쁘고, 움직일 때 더 좋아 보여야 해.

## 추천 인터랙션

* 카드 hover: `translateY(-2px)` 정도
* 버튼 hover: 배경 살짝 진해짐
* 검색창 focus: 외곽선 대신 부드러운 halo
* 페이지 로드: 부드러운 페이드 인
* 필터 적용: 급격한 깜빡임 없이 자연스럽게

## 피해야 할 것

* 카드가 너무 크게 확대되는 hover
* bounce
* 빠른 opacity 깜빡임
* 과한 parallax
* “멋있어 보이려고 넣은” 장식성 모션

# 11. 네가 바로 참고할 수 있는 “한 페이지 구조 초안”

아카이브 메인 페이지를 아주 단순하게 그리면 이런 느낌이야.

## 상단

* 고정 네비게이션

## 첫 섹션

* 큰 헤드라인
* 짧은 설명
* CTA 2개
* 우측에 아카이브 미리보기 mock card

## 두 번째 섹션

* 검색창
* 필터
* 정렬
* 보기 전환

## 세 번째 섹션

* Featured insight 큰 카드 1개

# 12. 가장 흔한 실수

이건 꼭 피하는 게 좋아.

## 실수 1

예쁜 컴포넌트를 많이 넣으면 좋아질 거라고 생각하는 것
→ 오히려 더 AI 템플릿 같아짐

## 실수 2

border를 너무 많이 씀
→ 관리툴 느낌 강해짐

## 실수 3

텍스트를 다 보여주려 함
→ 밀도만 높고 세련됨은 사라짐

## 실수 4

폰트만 바꾸면 분위기가 바뀔 거라고 생각함
→ 실제로는 spacing과 hierarchy가 훨씬 중요

## 실수 5

참고 사이트를 그대로 섞음
→ 일관성 없는 결과가 나옴

# 13. 최종 목표 상태

완성된 화면은 이런 인상을 줘야 해.

* “급하게 만든 개인 프로젝트”가 아니라
* “브랜드 의식이 있는 제품”
* “AI가 대충 만든 SaaS 템플릿”이 아니라
* “의도적으로 정제한 지식 아카이브”
* “기능이 많은 화면”이 아니라
* “다시 방문하고 싶은 화면”
