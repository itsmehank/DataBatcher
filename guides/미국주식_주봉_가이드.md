# DataBatcher US 주봉 테이블 실행 가이드

본 문서는 DataBatcher 프로젝트의 **미국 주식 주봉 테이블** 생성 및 업데이트 작업에 대한 실행 가이드입니다.

**최종 업데이트**: 2026-02-05

> **중요**: 주봉 가격/지표 모두 **INSERT ONLY**로 동작합니다.
> - 기존 row가 있으면 UPDATE하지 않고 PASS(멱등성 보장)
> - 목적: 이미 계산된 주봉/지표를 덮어써서 바뀌는 일을 방지

## 프로젝트 개요

US 주봉 테이블은 US 일봉 데이터를 주 단위로 집계하여 생성됩니다.

**핵심 파이프라인**: US 일봉 데이터 조회 → 주봉 집계 → 주봉 지표 계산 → DB 저장

**지원 마켓**: NYSE, NASDAQ, ETF

## 1. 사전 요구사항

### 필수 선행 작업

US 주봉 테이블 작업을 시작하기 전에 **반드시** 다음 작업이 완료되어야 합니다:

1. **US 일봉 데이터 수집 완료**
   - `us_bulk_update.py`로 과거 US 일봉 데이터가 수집되어 있어야 함
   - `us_stock_prices` 테이블에 데이터 존재 필요

2. **데이터베이스 스키마 적용**
   - `us_stock_prices_weekly`, `us_stock_indicators_weekly` 테이블 존재 확인
   - 마이그레이션: `scripts/migrations/add_us_weekly_tables.sql`

3. **설정 파일 확인**
   - `config/settings.yaml`에 `indicators_us_weekly` 섹션 존재

## 2. 최초 설치 및 실행 (Quick Start)

US 주봉 테이블을 처음 시작하는 경우:

**전제 조건**: US 일봉 데이터가 이미 수집되어 있어야 합니다.

**예상 소요 시간**: 10-20분

```bash

python scripts/tests/db_us_assert_weekly_tables_exist.py

# 2. 주봉 테이블 초기 데이터 생성 (symbol 정렬 기준 상위 100개 종목, DB 전체 기간)
python scripts/us_bulk_update_weekly.py --top 100

# 3. 주봉 증분 업데이트 테스트 (symbol 정렬 기준 상위 10개 종목)
python scripts/us_weekly_update.py --all --top 10
```

## 3. 상세 실행 가이드

### Step 1: 테이블 존재 확인

```bash
python scripts/tests/db_us_assert_weekly_tables_exist.py
```

```
  v_us_stock_price_weekly_with_ma: OK
```

### Step 2: US 일봉 데이터 존재 확인

```bash
python -c "
from core.config_loader import load_settings
from core.db_manager import DBConfig, DBManager
from sqlalchemy import text
cfg = load_settings()
engine = DBManager.get_engine(DBConfig(**cfg['database']))
with engine.connect() as conn:
    r = conn.execute(text('SELECT COUNT(DISTINCT symbol), COUNT(*), MIN(date), MAX(date) FROM us_stock_prices'))
    print(r.fetchone())
"
```

### Step 3: 과거 주봉 데이터 일괄 생성 (Bulk Collection)

**목적**: 모든 US 종목의 과거 일봉 데이터를 주봉으로 집계

```bash
# 전체 US 마켓, DB 전체 기간 주봉 생성 (가장 일반적)
python scripts/us_bulk_update_weekly.py

# NASDAQ만, 특정 기간
python scripts/us_bulk_update_weekly.py --market NASDAQ --start 2020-01-01 --end 2024-12-31

# symbol 정렬 기준 상위 100개만 (테스트)
python scripts/us_bulk_update_weekly.py --top 100
```

**예상 소요 시간**:
| 범위 | 소요 시간 |
|------|----------|
| 상위 100개, 1년 | 3-5분 |
| NASDAQ 전체, 1년 | 10-15분 |
| 전체 종목, 1년 | 20-30분 |

### Step 4: 주봉 증분 업데이트 테스트

```bash

python scripts/us_weekly_update.py --all

# 특정 마켓만
python scripts/us_weekly_update.py --all --market NASDAQ
```

## 4. 정규 운영 방법

### 4.1. 주간 작업: US 주봉 업데이트

**실행 주기**: 매주 토요일 (금요일 US 장마감 데이터 확정 후)

```bash
python scripts/us_weekly_update.py --all
```

**동작 방식**:
1. 최근 250주 일봉 데이터 조회 (us_stock_prices)
2. 주봉으로 집계
3. 주봉 가격 저장: INSERT ONLY
4. 주봉 지표 계산 (warmup 포함)
5. 최신 주부터 역순 처리:
   - 모든 지표가 완료된 주 만나면 중단 (조기 종료)
   - 누락된 주만 지표 INSERT ONLY

**주봉 날짜 규칙**:
- `week_start`: 해당 주의 첫 거래일 (월요일 고정 아님)
- `week_end`: 해당 주의 마지막 거래일

**로그 해석 주의**:
- `주봉 가격 N건 처리(insert-only)`의 `N`은 처리 건수이며 실제 신규 삽입 건수와 다를 수 있습니다.

### 4.2. 일봉과 주봉의 실행 순서

```
[매일 평일 22:00 KST (16:00 ET 이후)]
us_daily_update.py --all --with-indicators
↓
[매주 토요일 10:00 KST]
us_weekly_update.py --all
```

## 6. 설정 시스템

### 6.1. 주봉 설정 위치

`config/settings.yaml`의 `indicators_us_weekly` 섹션:

```yaml
indicators_us_weekly:
  materialization:
    mode: long
    table_long: us_stock_indicators_weekly
  pipeline:
    - name: sma
      params: { window: 20, column: close }  # 20주 (약 5개월)
      save: true
    - name: sma
      params: { window: 50, column: close }  # 50주 (약 1년)
      save: true
    - name: sma
      params: { window: 100, column: close } # 100주 (약 2년)
      save: true
    - name: sma
      params: { window: 200, column: close } # 200주 (약 4년)
      save: true
    - name: ema
      params: { window: 21, column: close }
      save: true
```

## 8. FAQ 및 트러블슈팅

### Q1. 주봉 데이터가 생성되지 않음

**원인**: US 일봉 데이터가 없음

**확인**:
```bash
python scripts/tests/db_us_assert_weekly_counts.py --symbol AAPL --start 2024-01-01 --end 2024-12-31
```

**해결**:
```bash
# 먼저 US 일봉 데이터 수집
python scripts/us_bulk_update.py --start 2024-01-01 --end 2024-12-31 --top 100

# 그 다음 주봉 생성
python scripts/us_bulk_update_weekly.py --top 100
```

### Q2. 일봉과 주봉 데이터 일관성 검증

```sql
SELECT w.week_start, w.volume as weekly_vol,
       (SELECT SUM(volume) FROM us_stock_prices d
        WHERE d.symbol = w.symbol AND d.date BETWEEN w.week_start AND w.week_end) as daily_sum
FROM us_stock_prices_weekly w WHERE w.symbol = 'AAPL' LIMIT 5;
```

### Q3. 테스트 데이터 정리

```bash
# dry-run으로 삭제 대상 확인
python scripts/tests/db_us_weekly_cleanup.py --symbol AAPL --start 2024-01-01 --end 2024-03-31 --dry-run

# 실제 삭제
python scripts/tests/db_us_weekly_cleanup.py --symbol AAPL --start 2024-01-01 --end 2024-03-31
```

### Q4. 멱등성 테스트

```bash
python scripts/tests/test_us_weekly_update_idempotency.py --symbol AAPL --start 2024-01-01 --end 2024-03-31
```

### Q5. 재실행 시에도 "주봉 가격 N건 처리(insert-only)"가 크게 보임

정상 동작일 수 있습니다. `N`은 처리 건수이며, `INSERT IGNORE` 특성상 중복 키는 DB에서 무시됩니다.

**해석 방법**:
- 가격 로그는 처리량 지표로 확인
- 실제 신규 적재 여부는 최신 주 추가 여부/테이블 row 증가로 확인
