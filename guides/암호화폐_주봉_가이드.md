# DataBatcher 실행 가이드 (Crypto Weekly / Binance Spot)

본 문서는 DataBatcher 프로젝트에서 **Binance Spot(USDT) 코인 주봉(1w) 데이터**를 생성/적재/업데이트하기 위한 **기능 개발 가이드(=계획서)** 입니다.

- 주식 주봉 가이드: `주봉테이블_작업가이드.md`
- 코인 일봉 가이드: `암호화폐_적재작업_가이드.md`

**최종 업데이트**: 2026-02-03

---

## 0. 목표/범위(이번 개발에서 무엇을 만들지)

### 0.1 목표
- Binance Spot(USDT) 코인 주봉(1w) OHLCV를 적재한다.
- 주식 주봉 파이프라인과 동일한 운영 경험을 제공한다.
  - 1회성 과거 적재(bulk)
  - 주기적 증분 적재(weekly_update)
- 저장은 **INSERT ONLY**로 멱등성 보장(재실행해도 기존 데이터 업데이트/변경 없음)

### 0.2 Phase 1 범위(확정)
1) 코인 주봉 가격 테이블 생성
- `crypto_prices_weekly`

2) 코인 주봉 지표 테이블 생성 + 지표 적재
- `crypto_indicators_weekly`
- 지표: **SMA(20/50/100/200, close)** + **EMA(21, close)**

### 0.3 비목표(Phase 2+)
- 코인 월봉/시간봉 지원
- Binance Futures(선물) 지원

## 1. 주봉 정의(week boundary) — 확정

코인 주봉은 **UTC 기준 월요일~일요일**을 1주로 정의합니다.

- `week_start`: 해당 주의 **UTC 월요일 날짜(DATE)**
- `week_end`: 해당 주의 **UTC 일요일 날짜(DATE)** (= week_start + 6 days)

> 주의: 이번 구현은 주봉 생성에 Binance `interval=1w` API를 사용합니다.
> 따라서 Binance가 반환하는 1w 캔들의 open time이 **UTC 월요일 00:00**을 기준으로 하는지 확인이 필요합니다.
> 검증: `scripts/tests/test_crypto_binance_klines_1w_live.py`로 확인 결과, Binance 1w 캔들의 open time은 **UTC 월요일 00:00:00** 기준입니다.

## 2. 주봉 생성 방식 — 확정(추천 변경)

### 2.1 Binance `interval=1w` 사용(확정)
- `GET /api/v3/klines` 사용
  - `interval=1w`
  - `startTime`, `endTime`으로 기간 필터
- 반환되는 1w 캔들의
  - open/high/low/close 사용
  - volume은 **quoteAssetVolume**을 주봉 volume(quote)으로 사용

### 2.2 주봉 기간/완결성(중요)
- 코인은 24/7이므로 “주말에 실행” 같은 KST 개념이 아니라, **UTC 기준으로 완결 여부를 판단**합니다.
- 기본 정책(권장): **현재 진행 중인 최신 주(이번 주)는 스킵하고, 완결된 주까지만 저장**
  - 예: 오늘이 UTC 수요일이면 이번 주는 미완결 → 스킵
  - 예: 오늘이 UTC 월요일이면 지난 주는 완결 → 포함

## 3. 스키마 설계(추가 테이블)

### 3.1 `crypto_prices_weekly`

권장 컬럼(주식 주봉 테이블과 유사)
- `symbol` VARCHAR(32) NOT NULL
- `week_start` DATE NOT NULL
- `week_end` DATE NOT NULL
- `open`, `high`, `low`, `close` DECIMAL
- `volume_quote` DECIMAL  (quoteAssetVolume)
- `exchange` VARCHAR(16) NOT NULL (예: BINANCE)
- `source` VARCHAR(16) NOT NULL (예: binance)
- `etl_loaded_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

PK
- `(symbol, week_start)`

인덱스
- `(week_start)`, `(symbol, week_start)`

### 3.2 `crypto_indicators_weekly`

권장 컬럼(일봉 지표 테이블과 동일한 long-form)
- `symbol` VARCHAR(32) NOT NULL
- `week_start` DATE NOT NULL
- `indicator` VARCHAR(64) NOT NULL
- `params_hash` CHAR(40) NOT NULL
- `value` DECIMAL(28,10) NULL
- `exchange` VARCHAR(16) NOT NULL
- `source` VARCHAR(16) NOT NULL
- `etl_loaded_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

PK
- `(symbol, week_start, indicator, params_hash)`

## 4. 설정(config/settings.yaml) 설계 — 확정

코인 주봉 지표는 별도 섹션으로 관리합니다.

```yaml
indicators_crypto_weekly:
  materialization:
    mode: long
    table_long: crypto_indicators_weekly
  pipeline:
    - name: sma
      params: { window: 20, column: close }
      save: true
    - name: sma
      params: { window: 50, column: close }
      save: true
    - name: sma
      params: { window: 100, column: close }
      save: true
    - name: sma
      params: { window: 200, column: close }
      save: true
    - name: ema
      params: { window: 21, column: close }
      save: true
```

## 5. 구현 계획(파일별)

### 5.1 스키마/초기화
- `docker/mysql/init/01_schema.sql`
  - `crypto_prices_weekly`, `crypto_indicators_weekly` CREATE TABLE 추가
- `scripts/init_db.py`
  - 위 테이블을 생성하도록 반영
- `docs/database_schema.md`
  - 테이블 정의 문서 업데이트

### 5.2 Collector 확장(Binance 1w)
- 수정: `collectors/crypto_binance.py`
  - `fetch_klines_1w(symbol: str, start: date, end: date) -> pd.DataFrame` 추가
  - 반환 컬럼(권장):
    - `symbol, week_start, open, high, low, close, volume_quote, exchange, source`
  - week_start 계산:
    - kline openTime(ms) → UTC datetime → UTC date
    - Binance 경계가 확정한 월요일 00:00 UTC인지 확인(테스트 포함)
  - volume_quote:
    - `quote_asset_volume` 사용

### 5.3 scripts: bulk(과거 1회성)
- 신규: `scripts/crypto_bulk_update_weekly.py`
  - 대상 심볼 결정 우선순위:
    1) `--all` → `crypto_symbol_master` ACTIVE
    2) `--symbols ...`
    3) config `crypto.targets.symbols`
  - 기간(현재 구현):
    - `--start/--end`를 필수로 받음(UTC date)
    - (개선 아이디어) 향후 `crypto_prices_daily`의 전체 기간(min/max date) 자동 탐색 옵션 추가 가능
  - 저장:
    - `crypto_prices_weekly`: insert_only
    - `--with-indicators`:
      - `crypto_indicators_weekly`: insert_only
      - keep_nan=True로 NULL 저장(일봉/주봉 정책과 동일)

### 5.4 scripts: weekly_update(증분)
- 신규: `scripts/crypto_weekly_update.py`
  - 기본: 완결된 주까지만 포함
  - end date(UTC):
    - 기본값: `UTC 오늘 - 1 day` (완결된 일/주 캔들만 보장)
    - `--end YYYY-MM-DD`로 고정 실행 가능(테스트/재현 목적)
  - 최신 주 스킵 정책(UTC):
    - 기본값: 최신 주 1개 드롭(안전장치)
    - 옵션:
      - `--skip-latest-week` (명시적으로 최신 주 드롭)
      - `--no-skip-latest-week` (최신 주를 드롭하지 않음)
  - 지표:
    - `indicators_crypto_weekly`로 pipeline 구성
    - (현행) 완료 체크 로직은 구현하지 않고, insert-only 멱등성 + 검증 스크립트로 확인
    - (Phase 2) 필요 시 week_start별 row 수(expected spec 수) 기반 완료 체크 추가
