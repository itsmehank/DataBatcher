### 주봉 테이블 생성 작업 계획 가이드

프로젝트 구조를 분석한 결과, 현재 일봉 데이터 처리 방식을 기반으로 주봉 테이블 작업을 설계하는 방법을 다음과 같이 제안합니다.

---

## 1. 주봉 테이블 구조

### 1.1 테이블 설계

일봉과 동일하게 **가격 테이블**과 **지표 테이블**을 분리하여 생성하는 것을 권장합니다:

```sql
-- 주봉 가격 테이블
CREATE TABLE IF NOT EXISTS stock_prices_weekly (
  symbol        VARCHAR(32)  NOT NULL,
  week_start    DATE         NOT NULL,  -- 주의 시작일(월요일)
  week_end      DATE         NOT NULL,  -- 주의 종료일(금요일)
  open          DECIMAL(18,4),
  high          DECIMAL(18,4),
  low           DECIMAL(18,4),
  close         DECIMAL(18,4),
  adj_close     DECIMAL(18,4) NULL,
  volume        BIGINT,
  market        VARCHAR(16) NOT NULL,
  source        VARCHAR(16) NOT NULL,
  etl_loaded_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (symbol, week_start),
  KEY idx_week_start (week_start),
  KEY idx_market_week (market, week_start)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 주봉 지표 테이블
CREATE TABLE IF NOT EXISTS stock_indicators_weekly (
  symbol        VARCHAR(32) NOT NULL,
  week_start    DATE        NOT NULL,
  indicator     VARCHAR(64) NOT NULL,
  params_hash   CHAR(40)    NOT NULL,
  value         DECIMAL(28,10) NULL,
  market        VARCHAR(16) NOT NULL,
  source        VARCHAR(16) NOT NULL,
  etl_loaded_at TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (symbol, week_start, indicator, params_hash),
  KEY idx_indicator_week (indicator, week_start),
  KEY idx_symbol_week (symbol, week_start)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**설계 이유:**
- 일봉과 동일한 구조를 유지하여 코드 재사용성 극대화
- `week_start`를 기본키로 사용하여 주 단위 데이터 식별
- Long-form 지표 테이블로 다양한 지표를 유연하게 저장

## 2. 스크립트 구조 (Bulk vs Incremental)

### 2.1 권장 방식: 2개의 스크립트로 분리

**결론: 네, 주봉도 2개의 스크립트로 나누는 것을 권장합니다.**

#### Option A: 완전히 독립적인 스크립트 (권장)

```
scripts/
├── bulk_update_weekly.py       # 주봉 전체 데이터 초기 적재
└── weekly_update.py            # 주봉 증분 업데이트
```

**장점:**
- 일봉과 완전히 분리된 실행 흐름
- 각 timeframe별 독립적인 에러 처리
- 유지보수 및 디버깅 용이

**단점:**
- 코드 중복 가능성 (하지만 공통 모듈화로 해결 가능)

#### Option B: 단일 스크립트 방식 (대안)

```
scripts/
└── weekly_update.py            # --full 옵션으로 bulk/incremental 통합
```

**장점:**
- 스크립트 수 감소
- 설정 및 실행 단순화

**단점:**
- 스크립트 복잡도 증가
- 일봉 패턴(bulk + daily)과 일관성 저하

### 2.2 추천 구현 방식

**Option A (독립 스크립트)**를 추천하며, 다음과 같이 구현:

#### `scripts/bulk_update_weekly.py`
```python
# 최초 1회 실행: 과거 전체 주봉 데이터 생성
# 
# 실행 방법:
# python scripts/bulk_update_weekly.py --start 2020-01-01 --end 2024-12-31 --workers 4
#
# 동작:
# 1. DB에서 일봉 데이터 조회
# 2. 주 단위로 OHLCV 집계 (월~금)
# 3. stock_prices_weekly에 INSERT
# 4. 주봉 기준 지표 계산
# 5. stock_indicators_weekly에 INSERT
```

#### `scripts/weekly_update.py`
```python
# 정기 실행: 최근 주봉 데이터 업데이트
#
# 실행 방법:
# python scripts/weekly_update.py --all
#
# 동작:
# 1. 최근 N주 일봉 데이터 조회 (예: 60주)
# 2. 주 단위 집계
# 3. 최신 주봉만 UPSERT (INSERT ON DUPLICATE KEY UPDATE)
# 4. 지표 계산 및 UPSERT
# 5. Smart early termination (완료된 주 발견 시 중단)
```

## 3. 데이터 생성 방식

### 3.1 주봉 생성 로직

주봉 데이터는 **일봉 데이터를 집계**하여 생성하는 방식을 권장:

```python
# 예시 로직
def aggregate_daily_to_weekly(daily_df: pd.DataFrame) -> pd.DataFrame:
    """일봉 데이터를 주봉으로 집계"""
    daily_df['week_start'] = daily_df['date'].dt.to_period('W-FRI').dt.start_time.dt.date
    
    weekly_df = daily_df.groupby(['symbol', 'week_start']).agg({
        'open': 'first',      # 주의 첫 거래일 시가
        'high': 'max',        # 주 최고가
        'low': 'min',         # 주 최저가
        'close': 'last',      # 주의 마지막 거래일 종가
        'volume': 'sum',      # 주 거래량 합계
        'market': 'first',
        'source': 'first'
    }).reset_index()
    
    return weekly_df
```

**이유:**
- FDR API는 주봉 데이터를 직접 제공하지 않음 (일봉만 제공)
- 일봉 기반 집계가 데이터 정합성 보장
- 공휴일/휴장일 처리 자동화

## 4. 스케줄링 전략

### 4.1 실행 시점

#### 일봉 작업
- **daily_update.py**: 매 영업일 17:00 (장마감 후 30분)

#### 주봉 작업
- **weekly_update.py**: 매주 토요일 새벽 02:00 (주말)
- **bulk_update_weekly.py**: 최초 1회만 실행 (또는 재구축 시)

### 4.2 Cron 예시

```bash
# /etc/crontab 또는 crontab -e

# 일봉: 매 영업일 17:00
0 17 * * 1-5 cd /path/to/DataBatcher && source .venv/bin/activate && python scripts/daily_update.py --all --force >> logs/daily_update.log 2>&1

# 주봉: 매주 토요일 새벽 2시
0 2 * * 6 cd /path/to/DataBatcher && source .venv/bin/activate && python scripts/weekly_update.py --all >> logs/weekly_update.log 2>&1

# 종목 마스터: 매주 일요일 새벽 2시
0 2 * * 0 cd /path/to/DataBatcher && source .venv/bin/activate && python scripts/sync_symbol_master.py >> logs/sync_symbol_master.log 2>&1
```

### 4.3 실행 순서 고려사항

**토요일 새벽에 주봉 업데이트하는 이유:**
1. 금요일 장마감 데이터가 `daily_update.py`로 이미 수집됨
2. 주말에 실행하여 서버 부하 분산
3. 일주일 데이터가 완전히 확정된 시점

**의존성:**
- 주봉 업데이트는 일봉 데이터에 의존
- 따라서 일봉이 먼저 완료되어야 함 (자동으로 보장됨)

### 5.3 권장 사항

**동일 파일 방식 (settings.yaml)을 추천하는 이유:**

✅ **장점:**
- 설정 파일 개수 최소화
- 일봉/주봉 설정 비교 용이
- 환경별 오버라이드 단순 (`settings.dev.yaml`에서 한 번에 처리)
- 버전 관리 편의성

❌ **분리 방식의 단점:**
- 설정 파일 수 증가 (settings.yaml, settings.dev.yaml, settings.weekly.yaml, settings.weekly.dev.yaml...)
- 일봉/주봉 설정 동기화 필요 시 번거로움
- 코드에서 설정 로드 로직 복잡화

**단, 다음 경우에는 분리 고려:**
- 주봉 지표가 매우 많고 복잡한 경우 (20개 이상)
- 월봉, 분봉 등 추가 timeframe 확장 계획이 있는 경우
- 주봉과 일봉의 운영 환경이 완전히 다른 경우

## 7. 코드 재사용 전략

### 7.1 공통 모듈 활용

기존 `daily_update.py`와 최대한 코드를 공유하기 위해 공통 모듈 생성:

```python
# core/timeframe_processor.py (새로 생성)

class TimeframeProcessor:
    """일봉/주봉 처리 공통 로직"""
    
    def __init__(self, timeframe: str, config: dict):
        self.timeframe = timeframe  # 'daily' or 'weekly'
        self.config = config
        
    def aggregate_prices(self, daily_df: pd.DataFrame) -> pd.DataFrame:
        """일봉을 지정된 timeframe으로 집계"""
        if self.timeframe == 'daily':
            return daily_df
        elif self.timeframe == 'weekly':
            return self._aggregate_to_weekly(daily_df)
    
    def get_price_table(self) -> str:
        return f"stock_prices_{self.timeframe}" if self.timeframe != 'daily' else "stock_prices"
    
    def get_indicator_table(self) -> str:
        return f"stock_indicators_{self.timeframe}" if self.timeframe != 'daily' else "stock_indicators"
```

### 7.2 스크립트에서 활용

```python
# scripts/weekly_update.py

from core.timeframe_processor import TimeframeProcessor

def main():
    processor = TimeframeProcessor('weekly', cfg)
    
    # 공통 로직 재사용
    price_table = processor.get_price_table()  # 'stock_prices_weekly'
    indicator_table = processor.get_indicator_table()  # 'stock_indicators_weekly'
    
    # ...
```

## 8. 주봉 지표 선택 가이드

### 8.1 일봉 vs 주봉 지표 차이

**일봉 (단기 트레이딩)**
- SMA(5, 20) - 1주, 1개월
- EMA(12, 26) - MACD 계산용
- RSI(14) - 과매수/과매도

**주봉 (장기 투자)**
- SMA(4, 13, 26) - 1개월, 3개월, 6개월
- EMA(12, 26) - 장기 추세
- RSI(14) - 주 단위 과열 판단

### 8.2 권장 주봉 지표 설정

```yaml
indicators_weekly:
  pipeline:
    # 이동평균
    - name: sma
      params: { window: 4, column: close }    # 약 1개월
    - name: sma
      params: { window: 13, column: close }   # 약 3개월 (분기)
    - name: sma
      params: { window: 26, column: close }   # 약 6개월 (반기)
    - name: sma
      params: { window: 52, column: close }   # 약 1년
    
    # 지수이동평균
    - name: ema
      params: { window: 12, column: close }
    - name: ema
      params: { window: 26, column: close }
    
    # 추가 가능한 지표들
    # - name: rsi
    #   params: { window: 14, column: close }
    # - name: macd
    #   params: { fast: 12, slow: 26, signal: 9, column: close }
```

## 9. 데이터 검증 쿼리

### 9.1 주봉 데이터 확인

```sql
-- 주봉 가격 데이터 확인
SELECT 
  COUNT(DISTINCT symbol) as symbols,
  COUNT(*) as weekly_rows,
  MIN(week_start) as oldest,
  MAX(week_start) as newest
FROM stock_prices_weekly;

-- 주봉 지표 확인
SELECT 
  indicator,
  COUNT(*) as rows
FROM stock_indicators_weekly
GROUP BY indicator;

-- 특정 종목의 주봉 확인
SELECT * 
FROM stock_prices_weekly 
WHERE symbol = '005930' 
ORDER BY week_start DESC 
LIMIT 10;
```

### 9.2 일봉-주봉 일관성 검증

```sql
-- 일봉과 주봉의 종가 비교 (금요일)
SELECT 
  d.symbol,
  d.date,
  d.close as daily_close,
  w.close as weekly_close,
  w.week_start,
  w.week_end
FROM stock_prices d
JOIN stock_prices_weekly w 
  ON d.symbol = w.symbol 
  AND d.date BETWEEN w.week_start AND w.week_end
WHERE DAYOFWEEK(d.date) = 6  -- 금요일
  AND d.symbol = '005930'
ORDER BY d.date DESC
LIMIT 10;
```
