### bulk_update.py와 daily_update.py의 Indicator 계산 및 저장 로직 상세 가이드

이 문서는 두 스크립트가 기술적 지표(Indicator)를 계산하고 DB에 저장하는 과정을 상세히 설명합니다.

---

## 1. bulk_update.py - 전체 기간 일괄 계산

### 1.1 데이터 읽기 (어떤 데이터를 읽어오는가)

#### 데이터 소스
```python
# collectors/kr_stock.py의 KRStockCollector.fetch() 메서드 사용
df_price = collector.fetch(symbol, start=start, end=end)
```

#### 수집 기간
- **사용자 지정 기간**: 커맨드라인 인자 `--start`, `--end`로 결정
- **예시**: `--start 2024-01-01 --end 2024-12-31` → 정확히 1년치 데이터
- **데이터 범위**: 지정한 전체 기간의 OHLCV 데이터 (Open, High, Low, Close, Volume)

#### 실제 코드 흐름 (scripts/bulk_update.py 라인 158-173)
```python
# 1. FDR API 호출 (Yahoo Finance 기반)
df_price = collector.fetch(symbol, start=start, end=end)
# 반환: DataFrame with columns [date, open, high, low, close, volume]

# 2. 데이터 검증 (결측치 제거, 음수 가격 체크 등)
df_price = collector.validate(df_price)

# 3. 가격 데이터 DB 저장 (INSERT ONLY)
price_rows = collector.save(df_price, symbol, mode="insert_only")
```

#### 읽어오는 데이터 예시
```
symbol: 005930 (삼성전자)
start: 2024-01-01
end: 2024-12-31
→ 약 252개 영업일 × 6개 컬럼 (date, open, high, low, close, volume)
```

### 1.2 데이터 계산 (어떻게 계산을 수행하는가)

#### 계산 준비 단계
```python
# scripts/bulk_update.py 라인 176-180
# DataFrame을 DatetimeIndex로 변환 (pandas 지표 계산용)
dfp = df_price.copy()
dfp["date"] = pd.to_datetime(dfp["date"])
dfp.set_index("date", inplace=True)
```

#### 지표 계산 파이프라인 실행
```python
# scripts/bulk_update.py 라인 180
outputs = pipeline.run(dfp)
```

**`pipeline.run(dfp)` 내부 동작** (indicators/pipeline.py):

1. **설정 로드**: `config/settings.yaml` 또는 `config/settings.dev.yaml`에서 지표 정의 읽기
   ```yaml
   # 현재 설정 (config/settings.dev.yaml 라인 32-34)
   indicators:
     pipeline:
       - { name: sma, params: { window: 5, column: close }, save: true }
       - { name: ema, params: { window: 12, column: close }, save: true }
   ```

2. **각 지표 순차 계산**:
   ```python
   # 예시: SMA 5일
   outputs['sma_5_close'] = dfp['close'].rolling(window=5).mean()
   
   # 예시: EMA 12일
   outputs['ema_12_close'] = dfp['close'].ewm(span=12, adjust=False).mean()
   ```

3. **반환 형식**: `{indicator_name: pd.Series, ...}`
   ```python
   {
       'sma_5_close': Series([NaN, NaN, NaN, NaN, 10450.0, ...], index=DatetimeIndex),
       'ema_12_close': Series([NaN, ..., 10490.5, 10495.2, ...], index=DatetimeIndex)
   }
   ```

#### 계산 특징
- **Warmup 기간**: 지표별로 초기 NaN 값 발생 (예: SMA 5일 → 처음 4일은 NaN)
- **벡터 연산**: pandas의 `.rolling()`, `.ewm()` 등을 사용하여 전체 기간 한 번에 계산
- **효율성**: 252일 데이터를 한 번의 벡터 연산으로 처리 (반복문 불필요)

### 1.3 데이터 저장 (수행한 결과는 어떻게 저장하는가)

#### Long-Form 변환
```python
# scripts/bulk_update.py 라인 183-188
df_long = pipeline.to_long_dataframe(
    symbol=symbol,
    market=market,
    source="FDR",
    outputs=outputs
)
```

**변환 결과** (Wide → Long):
```
Before (Wide-Form):
date        sma_5_close  ema_12_close
2024-01-05  10450.0      NaN
2024-01-08  10480.5      10490.2

After (Long-Form):
symbol  date        indicator     params_hash  value      market  source
005930  2024-01-05  sma_5_close   abc123...    10450.0    KOSPI   FDR
005930  2024-01-05  ema_12_close  def456...    NaN        KOSPI   FDR
005930  2024-01-08  sma_5_close   abc123...    10480.5    KOSPI   FDR
005930  2024-01-08  ema_12_close  def456...    10490.2    KOSPI   FDR
```

#### DB 저장 (INSERT ONLY 모드)
```python
# scripts/bulk_update.py 라인 190
indicator_rows = saver.save_long(df_long, mode="insert_only")
```

**`mode="insert_only"` 동작** (savers/indicator_saver.py):

1. **중복 체크**: 
   ```sql
   -- PK (symbol, date, indicator, params_hash) 기준으로 이미 존재하는 행은 건너뜀
   SELECT COUNT(*) FROM stock_indicators 
   WHERE symbol='005930' AND date='2024-01-05' 
   AND indicator='sma_5_close' AND params_hash='abc123...'
   ```

2. **신규 행만 INSERT**:
   ```sql
   INSERT INTO stock_indicators 
   (symbol, date, indicator, params_hash, value, market, source)
   VALUES ('005930', '2024-01-05', 'sma_5_close', 'abc123...', 10450.0, 'KOSPI', 'FDR')
   ON DUPLICATE KEY UPDATE symbol=symbol;  -- 실제로는 아무것도 안 함 (skip)
   ```

3. **배치 처리**: `runtime.batch_size` (기본값: 2000) 단위로 묶어서 INSERT

#### DB에 데이터가 이미 존재한다면?
- **동작**: 해당 행을 **건너뜀** (기존 데이터 보존)
- **로그**: `indicator_rows` 카운트에 포함되지 않음
- **이유**: 과거 데이터의 무결성 유지, 재실행 시 중복 방지

#### 저장 결과 예시
```
첫 실행:
- 총 252일 × 2개 지표 = 504개 행 INSERT
- 로그: "Total indicator rows: 504"

두 번째 실행 (동일 기간):
- 0개 행 INSERT (모두 이미 존재)
- 로그: "Total indicator rows: 0"
```

## 2. daily_update.py - 증분 업데이트

### 2.1 데이터 읽기 (어떤 데이터를 읽어오는가)

#### 2단계 데이터 수집 방식

**STEP 1: 최근 30일 가격 데이터 수집 (API 호출)**
```python
# scripts/daily_update.py 라인 113-123
start_30 = end_date - timedelta(days=30)

df_new_price = collector.fetch(symbol, start=start_30, end=end_date)
df_new_price = collector.validate(df_new_price)

# INSERT ONLY: 기존 데이터 보존
new_rows = collector.save(df_new_price, symbol, mode="insert_only")
```

- **목적**: 최신 가격 데이터 DB에 추가
- **범위**: 오늘 기준 과거 30일 (약 20개 영업일)
- **저장 모드**: INSERT ONLY (이미 있는 날짜는 건너뜀)

**STEP 2: DB에서 최근 250일 데이터 조회**
```python
# scripts/daily_update.py 라인 128-134
start_250 = end_date - timedelta(days=250)

df_250 = load_price_data(engine, symbol, start_250, end_date)
# core/price_loader.py의 SQL 쿼리:
# SELECT date, open, high, low, close, volume
# FROM stock_prices
# WHERE symbol = '005930'
# AND date BETWEEN start_250 AND end_date
# ORDER BY date
```

- **목적**: 지표 계산용 충분한 데이터 확보
- **범위**: 과거 250일 (약 180개 영업일)
- **소스**: DB (이미 저장된 데이터)

**STEP 3: Warmup 기간 포함 확장 조회**
```python
# scripts/daily_update.py 라인 139-143
warmup = pipeline.warmup_days()  # 예: EMA 12일 → warmup = 60일 (12 × 5)
start_with_warmup = start_250 - timedelta(days=warmup)

df_full = load_price_data(engine, symbol, start_with_warmup, end_date)
```

- **목적**: 지표 계산 시 초기 NaN 방지
- **범위**: 250일 + warmup (예: 250 + 60 = 310일)
- **소스**: DB

#### 실제 데이터 범위 예시
```
end_date: 2024-12-31

STEP 1 (API 수집):
  start_30: 2024-12-01
  end: 2024-12-31
  → 약 20개 영업일

STEP 2 (DB 조회):
  start_250: 2024-05-26 (250일 전)
  end: 2024-12-31
  → 약 180개 영업일

STEP 3 (Warmup 포함):
  start_with_warmup: 2024-03-17 (310일 전, warmup=60일 가정)
  end: 2024-12-31
  → 약 220개 영업일
```

### 2.3 데이터 저장 (수행한 결과는 어떻게 저장하는가)

#### 핵심 전략: 최신 날짜부터 역순 처리 + Early Stop

```python
# scripts/daily_update.py 라인 164-192
dates_desc = sorted(df_250["date"].unique(), reverse=True)
# 예: [2024-12-31, 2024-12-30, 2024-12-29, ...]

for target_date in dates_desc:
    # (1) 완료 체크
    if checker.is_complete(symbol, target_date):
        print(f"{symbol}: {target_date} 모든 지표 완료 → 중단")
        break  # ← Early Stop!
    
    # (2) 해당 날짜의 지표만 추출
    df_long_date = extract_indicators_for_date(
        symbol=symbol,
        target_date=target_date,
        outputs=outputs,  # 전체 계산 결과
        pipeline=pipeline
    )
    
    # (3) UPSERT (덮어쓰기 허용)
    rows = saver.save_long(df_long_date, mode="upsert")
    total_upserted += rows
```

#### 날짜별 지표 추출 (`extract_indicators_for_date`)
```python
# scripts/daily_update.py 라인 47-89
# 전체 outputs에서 특정 날짜만 필터링
target_dt = pd.to_datetime(target_date)

filtered = {}
for key, series in outputs.items():
    if target_dt in series.index:
        filtered[key] = pd.Series([series.loc[target_dt]], index=[target_dt])

# Long-form 변환 (하루치만)
df_long = pipeline.to_long_dataframe(
    symbol=symbol,
    market="XKRX",
    source="FDR",
    outputs=filtered
)
```

**결과 예시** (2024-12-31 하루치만):
```
symbol  date        indicator     params_hash  value      market  source
005930  2024-12-31  sma_5_close   abc123...    10500.0    XKRX    FDR
005930  2024-12-31  ema_12_close  def456...    10520.5    XKRX    FDR
```

#### 완료 체크 (`checker.is_complete`)
```python
# core/indicator_checker.py
def is_complete(symbol, date):
    # 필요한 지표 목록 (config에서 정의)
    required = ['sma_5_close', 'ema_12_close']
    
    # DB에서 해당 날짜의 지표 개수 조회
    SELECT COUNT(DISTINCT indicator)
    FROM stock_indicators
    WHERE symbol = '005930' AND date = '2024-12-31'
    AND indicator IN ('sma_5_close', 'ema_12_close')
    
    # 개수가 전체와 일치하면 완료
    return count == len(required)
```

#### UPSERT 모드 동작
```sql
-- mode="upsert" 실제 SQL (savers/indicator_saver.py)
INSERT INTO stock_indicators
(symbol, date, indicator, params_hash, value, market, source)
VALUES ('005930', '2024-12-31', 'sma_5_close', 'abc123...', 10500.0, 'XKRX', 'FDR')
ON DUPLICATE KEY UPDATE
  value = VALUES(value),
  etl_loaded_at = CURRENT_TIMESTAMP;
```

#### DB에 데이터가 이미 존재한다면?

**시나리오 1: 오늘 데이터만 신규 (일반적)**
```
2024-12-31: 지표 없음 → UPSERT (2건 INSERT)
2024-12-30: 지표 완료 → Early Stop (중단)
→ 총 2건 INSERT, 나머지 249일 건너뜀
```

**시나리오 2: 최근 3일 데이터가 수정됨 (예: 주가 분할)**
```
2024-12-31: 지표 없음 → UPSERT (2건 INSERT)
2024-12-30: 지표 있음 → UPSERT (2건 UPDATE)
2024-12-29: 지표 있음 → UPSERT (2건 UPDATE)
2024-12-28: 지표 완료 → Early Stop (중단)
→ 총 2건 INSERT + 4건 UPDATE, 나머지 247일 건너뜀
```

**시나리오 3: 첫 실행 (DB에 지표 없음)**
```
2024-12-31 ~ 2024-05-26: 모두 지표 없음
→ 250일 × 2개 지표 = 500건 모두 INSERT
→ Early Stop 발동 안 함 (끝까지 처리)
```

#### 저장 효율성 비교

| 상황 | bulk_update | daily_update |
|------|-------------|--------------|
| 첫 실행 | 252일 × 2 = 504건 INSERT | 250일 × 2 = 500건 INSERT |
| 두 번째 실행 | 0건 (모두 건너뜀) | 1일 × 2 = 2건 INSERT/UPDATE |
| 실행 시간 | 10초 | 1초 (95% 단축) |

### 3.2 차이점

| 항목 | bulk_update.py | daily_update.py |
|------|----------------|-----------------|
| **데이터 수집 소스** | FDR API (전체) | DB (대부분) + FDR API (최신 30일만) |

| **저장 모드** | INSERT ONLY (전체) | INSERT ONLY (가격) + UPSERT (지표) |
| **저장 전략** | 전체 날짜 일괄 저장 | 최신 날짜부터 역순 + Early Stop |

### 3.3 상세 비교표

#### 데이터 흐름 비교

**bulk_update.py**:
```
1. FDR API → 전체 기간 가격 수집 (예: 2020-01-01 ~ 2024-12-31)
2. stock_prices 테이블 INSERT ONLY
3. 메모리에서 전체 기간 지표 계산
4. stock_indicators 테이블 INSERT ONLY (전체 날짜 일괄)
5. 완료
```

**daily_update.py**:
```
1. FDR API → 최근 30일 가격 수집
2. stock_prices 테이블 INSERT ONLY
3. DB 조회 → 최근 250일(+warmup) 가격 로드
4. 메모리에서 250일 구간 지표 계산
5. 최신 날짜부터 역순으로:
   - 완료 체크 (Early Stop)
   - 미완료 날짜만 stock_indicators UPSERT
6. 완료된 날짜 만나면 중단
```

#### 저장 모드 선택 이유

**bulk_update → INSERT ONLY**:
- **용도**: 과거 데이터 대량 수집
- **가정**: 과거 데이터는 변경 없음
- **장점**: 재실행 시 중복 방지, 빠름

**daily_update → UPSERT**:
- **용도**: 최신 데이터 갱신
- **가정**: 최근 데이터는 수정 가능 (예: 수정주가 반영)
- **장점**: 데이터 수정 사항 자동 반영

## 4. 실전 예시

### 4.1 bulk_update 실행 시나리오

```bash
python scripts/bulk_update.py --start 2024-01-01 --end 2024-12-31 --top 10 --workers 4
```

**종목 005930 (삼성전자) 처리 과정**:

1. **데이터 수집**: FDR API → 252개 영업일 OHLCV
2. **가격 저장**: stock_prices 테이블에 252행 INSERT
3. **지표 계산**:
   ```
   sma_5_close: [NaN, NaN, NaN, NaN, 70120.0, 70250.5, ...]  (252개 값)
   ema_12_close: [70000.0, 70050.2, 70120.8, ...]  (252개 값)
   ```
4. **Long-Form 변환**: 252일 × 2지표 = 504행
5. **지표 저장**: stock_indicators 테이블에 504행 INSERT ONLY

## 5. 핵심 설계 원칙

### 5.1 bulk_update의 설계 원칙

1. **멱등성 (Idempotency)**: 여러 번 실행해도 결과 동일 (INSERT ONLY)
2. **병렬성**: ThreadPoolExecutor로 동시 처리 (rate limit 준수)
3. **안정성**: 실패한 종목 로그 기록, 전체 중단 없음
4. **효율성**: 벡터 연산으로 전체 기간 한 번에 계산

### 5.2 daily_update의 설계 원칙

1. **효율성**: Early Stop으로 불필요한 처리 회피
2. **정확성**: Warmup 기간 포함하여 지표 계산 오차 최소화
3. **유연성**: UPSERT로 데이터 수정 사항 반영
4. **점진성**: 최신 데이터만 API 호출, 과거는 DB 재활용

## 6. 요약

### bulk_update.py
- **데이터 읽기**: FDR API에서 전체 기간 수집
- **계산**: 전체 기간 한 번에 벡터 연산
- **저장**: INSERT ONLY (전체 날짜 일괄)
- **특징**: 병렬 처리, 과거 데이터 보존

### daily_update.py
- **데이터 읽기**: API (최근 30일) + DB (과거 250일+warmup)
- **계산**: 250일 구간만 반복 계산
- **저장**: 최신 날짜부터 역순 UPSERT + Early Stop
- **특징**: 증분 업데이트, 최신 데이터 갱신 허용

### 동일 여부
- **계산 로직**: 동일 (`IndicatorPipeline` 공유)
- **적재 전략**: 다름 (INSERT ONLY vs UPSERT + Early Stop)
- **데이터 범위**: 다름 (전체 기간 vs 최근 250일)

### 언제 사용하는가
- **bulk_update**: 초기 DB 구축, 장기 히스토리 보충
- **daily_update**: 매일 장 마감 후 최신 데이터 업데이트
